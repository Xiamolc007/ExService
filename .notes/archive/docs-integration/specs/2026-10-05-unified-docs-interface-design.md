# 统一 Outline 访客与登录界面

日期：2026-10-05。

状态：界面方向与访客入口已获确认；本规格待用户审阅。尚未实施。

模块根目录：`.notes/docs-integration/`。后续 RFC 目录：`.notes/docs-integration/rfcs/`。

## 问题与已确认方向

当前集成模式把匿名访问交给 `apps/outline/app/scenes/WebsitePublic.tsx`：居中的公共目录、搜索和只读正文使用独立外观；登录后则进入原 Outline 工作区。用户认为这种体验割裂，确认采用共用 Outline 布局、按权限提供内容和操作的方向。

用户同时同意访客打开 `/docs/` 时显示公开文档集总览，左侧保留文档树，不自动打开某篇文档。

本设计替代 `.notes/archive/docs-integration/rfcs/outline-public-access-rfc.md` 中公共页面采用独立界面的实现选择；集合公开、草稿隔离、身份核验与文档授权规则继续以既有规格和 RFC 为准。

## 目标与范围

1. 访客、登录读者和编辑者使用同一组 Outline 布局、侧栏容器、品牌、导航行及正文排版组件；主题、侧栏尺寸、折叠与移动端行为一致。
2. 访客只看公开集合及其已发布文档，可浏览文档树、阅读和搜索。登录入口位于与账号菜单相同的侧栏区域。
3. 登录后依据真实授权扩展可见集合及操作，不因登录自动获得私有阅读权或编辑权。
4. 在公开文档中登录后回到原文档；退出成功后重新核验公开可见性并继续阅读，私有文档退出后返回公开总览。
5. 空目录、加载、失败及不可见页面均在统一布局中呈现，不回到独立的 Documents 页面。

实施重点在 Outline 子模块；Website 的退出确认页面需要配合返回导航。无需新增 Website HTTP operation、修改数据库模型或调整公开 Share 规则。

本期不统一两套 React 依赖、不重建编辑协作系统、不新增匿名账号、不提供匿名评论、收藏或历史版本。原生非集成 Outline 的行为保留。

## 界面与组件边界

### 共用布局

从现有登录布局抽出不要求身份的文档布局组合，供集成公共路由与登录路由共同使用。复用 `Layout`、侧栏容器、`SidebarBrand`、导航行与正文宽度/标题/目录样式，不复制完整布局或维护另一套访客 CSS。

登录专属的 WebSocket、通知、个人快捷键、拖拽写操作和用户配置加载继续放在身份层，只在身份有效且具备相应能力时挂载。匿名路由不调用要求用户或团队的 hook，也不构造虚假 User、Team、Share 或文档 policy。

公开与登录可以使用不同数据适配器，但输出给共用呈现组件的导航条目、激活状态和能力模型一致。组件不凭角色名称推断操作能力；登录操作使用现有服务端授权和 policy，访客写能力恒为关闭。

### 侧栏与首页

访客侧栏依次显示现有品牌、文档总览/搜索、公开集合与文档树、登录入口。草稿、最近访问、收藏、通知、设置、导入和新建入口不挂载。

访客总览在主区域列出公开集合名称、描述和进入链接；集合为空时显示正常空集合，所有公开集合为空时显示“暂无公开文档集”语义的本地化空状态。品牌、侧栏和登录入口仍可操作。

登录用户保留原 `/home` 工作区首页及个人功能，侧栏补充有权访问的内容。共用界面不要求登录首页必须与访客总览内容完全相同。

### 文档与搜索

匿名及登录 publicOnly 读者共享同一正文呈现组件，使用原 Outline 编辑器的只读能力、统一标题/面包屑、正文宽度、附件与标题目录。仅有公共 DTO 的阅读路径不挂载内部成员、访问记录、引用或历史副请求。

具备集合阅读/编辑权限的登录用户继续使用原文档场景；阅读框架与公开场景共用，同一文档的阅读样式保持一致。评论入口仅在有效身份与可读授权下出现，编辑/发布/管理使用现有能力。

搜索入口与结果布局共用：访客使用公共搜索，登录使用现有授权搜索。保留查询文本与 query string，切换身份后重新查询对应权限范围。结果只显示其数据投影实际提供的字段。

## 数据流与路由

### 公共导航

沿用以下真实 Outline RPC，不复制进 Website OpenAPI 或生成 Client：

| RPC                       | 用途                                               |
| ------------------------- | -------------------------------------------------- |
| `public.collections.list` | 公开集合目录，按既有 offset/limit/hasMore 分页。   |
| `public.documents.list`   | 指定公开集合的文档及可公开父节点关系。             |
| `public.documents.info`   | 公开正文及所属集合，用于深链接激活和公开状态复核。 |
| `public.documents.search` | 公开文档检索。                                     |

集合目录支持继续加载，不能把首页最多 100 条当作全部集合。文档树按集合展开加载，读完该集合所有分页再构建完整父子关系；加载过程中显示进度，失败允许重试，不把尚未加载的父节点误判为不存在。客户端以公开条目的 title、id 做稳定排序，不声称与内部人工排序完全相同。

直达公开文档时先取得正文所属集合，在公开集合列表中按页定位，加载该集合树并展开可见祖先。不得请求全部私有导航来定位。目录与正文请求共享导航级读取状态，避免同一集合重复拉取。

公共投影与登录实体 store 分离。身份或授权范围变化后作废旧请求，清理受保护导航、正文与评论状态；迟到结果不能重新注入当前界面。服务端仍逐次授权，不以客户端缓存作为访问依据。

### 路由兼容

对外地址继续挂载 `/docs`。保留现有 `/docs/`、`/docs/public/collection/:collectionId`、`/docs/doc/<slug>` 和 `/docs/search`；旧公共集合链接无需迁移。成员集合地址 `/docs/collection/<slug>` 继续用于原授权场景。

公开集合链接在登录后仍可打开同一公开总览场景，避免把它转换为需要额外权限的集合页面。文档 canonical、SSR、附件地址及 sitemap 保持原规则。

## 登录、退出与故障

### 登录

共用身份边界承接现有 WebsiteSessionProbe、自动 OIDC 接入和手动登录；仍校验 origin/source/nonce，保留现有超时与重复尝试限制。身份探测不阻塞公开导航和正文。

登录保存受验证的原文档/集合/搜索路径及查询。认证完成后恢复该路径并重新获取能力，避免根路径跳转把读者送到 `/home`。仅直接打开登录根入口时保留原工作区首页行为。

### 退出

退出仍通过既有服务端撤销流程，auth.delete 的固定 redirectUrl 及其验证保持不变。退出动作开始前记录当前安全阅读路径；AuthStore 在成功撤销后给固定 Website 确认页附带经过校验的返回提示。返回提示是导航信息，不包含 token、用户资料或文档正文，不作为授权凭证。

Website 仅在确认 signed-out 后自动返回安全的公共阅读路径。active 表示可能存在后来建立的新会话：不清理该会话、不自动重试退出，提供手动返回。unavailable 保留重试与手动阅读入口，不宣称会话已退出。

返回候选只接受同源 `/docs/` 总览、既有公开集合、文档和搜索路径；拒绝外域、编码穿越、反斜杠、控制字符以及 auth/logout/edit/history 等动作路径，失败回退 `/docs/`。返回公开文档时由匿名 resolver 重新判断当前可见性；私有、草稿或已撤销目标清空旧内容后回到公开总览，并显示通用不可用提示，不携带私有标题。

Outline 发起退出需要恢复阅读路径；Website 发起的既有退出行为保留。显式退出失败时显示失败并允许重试，不把一次失败伪装成匿名状态。

### 空状态与错误

- 加载、空结果、网络失败与授权不可见分别呈现，不把请求失败显示为没有公开内容。
- 私有、草稿、缺失文档使用同一不可见语义，保留既有服务端统一 404，不暴露隐藏名称或数量。
- 身份服务不可用时，公开接口和阅读继续可用；受保护动作仍拒绝并显示现有可重试状态。
- 文档/集合撤销公开后，下一次导航、刷新和正文复核清除不可读结果；不承诺收回已经传输的内容，也不新增实时公共撤销协议。
- 手机侧栏开关、键盘焦点、加载提示、树节点展开和主题使用原 Outline 可访问性与交互规范。

## 方案比较与选择

采用共用布局与呈现组件、按身份适配数据和能力。它能统一阅读体验，又允许原工作区个人功能继续独立受保护。

扩展原 Shared 场景需要把单 Share 导航转换为跨集合目录，并处理 Share 上下文与现有集成规范的差异，不能直接替代目标布局。完整工作区匿名化则会牵动大量强制用户/团队依赖及个人后台请求，范围过大。

仅给 WebsitePublic 添加仿制侧栏仍会留下两套维护路径，不满足本设计的组件复用要求。

## 验收条件

| 编号 | 场景与可观察结果                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------- |
| U01  | 全新匿名浏览器进入 `/docs/`，显示 Outline 布局、公开总览、侧栏树与登录入口。                              |
| U02  | 无公开集合、空集合、接口失败分别显示正确状态；侧栏始终可用。                                              |
| U03  | 多集合及超过 100 篇文档可完整加载，层级跨页不丢失；深链接激活正确文档与可见祖先。                         |
| U04  | 匿名请求与浏览器网络中不存在草稿、成员、通知、个人收藏等受保护副请求；私有标题和数量不可见。              |
| U05  | 匿名文档具有原阅读排版、只读正文、附件、目录与移动端侧栏；搜索使用公共权限。                              |
| U06  | 文档中登录后仍在原地址，登录读者可评论，编辑者仅对授权集合获得写操作；publicOnly 不挂载内部副请求。       |
| U07  | 公开文档退出成功后回到该文档，私有文档回到公开总览；退出失败、身份失联和后来建立的新会话分别正确处理。    |
| U08  | 身份变化后迟到请求不能恢复旧私有数据；登录失败不循环跳转，公开阅读保持可用。                              |
| U09  | 恶意返回路径回退总览；匿名草稿/私有/撤销文档仍统一不可见；公开 SSR、canonical、sitemap 和附件规则无回归。 |
| U10  | 非集成 Outline 路由、登录工作区个人功能及原协作能力维持既有行为。                                         |

组件/路由测试覆盖匿名树、分页、能力展示、身份切换及请求代次；真实 Koa 测试复用公共授权负向用例。Website 增补退出返回和新会话保护测试。修改区域按各仓库惯例做 typecheck、lint 与必要构建；若实施涉及 Website API 变更，必须另按 Contract-first 流程处理，不能借本规格绕过。

真实浏览器验收至少覆盖匿名、登录读者、指定集合编辑者、桌面与移动尺寸，以及身份服务不可用和退出恢复。报告 PASS/FAIL/NOT_EXECUTED，自动测试不替代布局与浏览器验收。

## 交付与后续

本规格待用户审阅；批准后用 technical-design-doc-creator 在 `.notes/docs-integration/rfcs/` 创建一份实施 RFC，具体明确呈现组件接口、导航状态、退出返回校验与测试落点。规格与 RFC 均留在父仓库，符合 Outline 子仓库不新增 Markdown 的规则。

本阶段只形成设计，不写生产代码、不提交或推送、不改 `.ai/`。后续实施按 Outline 子模块与 Website 的依赖顺序交付；回退代码与子模块引用即可恢复原公共界面，不涉及数据库或数据重置。若实现需要额外公开 RPC 或元数据字段，须在 RFC 中说明并评审，不能临时臆造接口。

目前无待选的产品方向；需要在实施 RFC 中完成的细节为具体共用呈现接口和安全导航返回实现。树使用既有分页，因此大型集合在完整加载前会显示等待状态；大规模树的专用 API 优化属于后续独立工作。
