# ExWebsite 与 Outline 集成设计

日期：2026-09-30

状态：分节需求已确认，完整规格待用户审阅；尚未实现或完成运行验证。

模块根目录：`.notes/archive/docs-integration/`。后续 RFC 位于 `.notes/archive/docs-integration/rfcs/`。

## 1. 目标与范围

在 ExWebsite 同域的 `/docs` 提供完整 Outline 阅读、编辑与协作能力。ExWebsite 保留账号、注册、登录和资料管理，独立部署 Ory Hydra 提供通用 OAuth2/OIDC 能力；Outline 为首个接入客户端。

本期交付为可在本机复现并完整验收的集成，包括两种运行模式、子仓库管理、统一身份、公开阅读、文档授权和会话撤销。公网部署、旧 Outline 数据迁移、开放应用自助注册、逐篇发布审批、多工作区和无关框架升级不在本期范围。

背景入口为 `.notes/archive/docs-integration/handoffs/2026-09-30-design-handoff.md`，原有产品术语见 `.ai/CONTEXT.md`。本文记录本轮进一步确认的设计；现有 `.ai/CONTEXT.md` 中“身份协议尚未确定”等描述属于本轮之前的背景，不能覆盖本文选择。完整规格批准后，另行征求是否将稳定结论同步到 `.ai/`。

### 已确认决策

| 主题 | 决策 |
| --- | --- |
| 运行模式 | 同时支持完整容器运行和本机应用热更新。 |
| 仓库组织 | Outline 以 Git submodule 位于 `apps/outline/`，保留 Yarn 和独立版本历史；排除于 Website pnpm workspace。 |
| ExUI | 当前继续链接本地 ExUI 源码，消费构建产物；不切换发布版或固定 tarball。用户发布更新后再单独切换。 |
| 身份来源 | Website 管理账号、凭据、资料及停用状态；Hydra 提供独立 OIDC 服务。 |
| 客户端管理 | 受控登记自有客户端；基础身份范围预先批准，不开放自助注册。 |
| 用户关联 | 固定 issuer 与稳定 sub，sub 对应 Website 账号 ID，不以邮箱关联身份。 |
| 初始化 | 全新 Outline、单工作区、显式指定首个管理员，普通首次访问不能创建工作区或自动取得管理员。 |
| 文档权限 | 登录用户可评论有权阅读的文档；默认不可新建或编辑；指定文档集授权后可新建、编辑。 |
| 文档集 | 仅文档管理员可创建文档集或改变公开状态，Website 管理员不自动映射。 |
| 发布 | 编辑者可直接发布与修改获授权文档；公开文档集内发布后可匿名阅读，草稿不公开。 |
| 分享 | 关闭单篇独立公开与匿名分享能力，保留受权限约束的普通链接复制。 |
| 退出 | Website 或 Outline 退出都撤销当前浏览器关联会话，其他设备保持登录。 |
| 状态核验 | 每次受保护请求核验 Website 会话及账号状态，无法确认时拒绝受保护操作；匿名公开阅读继续可用。 |
| 实时撤销 | 退出、停用或身份无法核验时，已有受保护连接最多 5 秒内停止受保护操作并断开。 |

以下技术拆分是落实上述决策的设计建议，具体数据表、HTTP 形状、版本和调用顺序由后续 RFC 固化，不能据此直接臆造 API。

## 2. 服务边界与运行拓扑

| 组件 | 责任 | 数据边界 |
| --- | --- | --- |
| 统一入口代理 | 分发 Website、`/docs`、Hydra 公共协议入口，转发 WebSocket | 不持有账号或文档业务数据 |
| Website Web / Server | 网站业务、登录 UI、登录与授权确认适配、会话权威、账号状态与资料 | 独立 `exre` 数据库及 Website 文件存储 |
| Hydra | OIDC 协议、客户端登记、授权码、令牌和协议会话 | 独立 Hydra 数据库，不读取 Website 用户表 |
| Outline | 文档、公开目录、权限、评论、编辑、协作及身份关联 | 独立 `outline` 数据库及附件存储 |
| Redis | Outline 所需队列、实时通知等；失效传播复用需按命名空间隔离 | 不作为 Website 账号状态的唯一事实来源 |

本地允许一个 PostgreSQL 实例承载三个独立数据库，应用使用各自受限账号。Website Server 的连接身份检查继续只接受 `exre`；Outline 和 Hydra 不能跨库修改 Website 数据。容器启动入口不能绕过现有显式 migration 规则。

Hydra 的公共协议入口与内部管理入口分离。浏览器和普通客户端不能访问管理 API；Website Server 通过内部网络或仅本机可达的开发连接访问它。Website 的新增 HTTP operation 仍由 `api/openapi.yaml` 定义，经 `@workspace/api-client` 调用；Hydra 自身协议路由和 Outline 原有 API 分别归各服务管理。

### 完整容器模式

根目录 Compose 编排代理、Website Web、Website Server、Outline、Hydra、PostgreSQL 和 Redis；构建本地 Website、Outline 与 ExUI。默认日常入口在初始化完成后可用一条命令启动全部服务。首次初始化、迁移和管理员指定使用明确的独立入口。

### 开发模式

代理、Hydra、PostgreSQL、Redis 在 Docker 运行；Website 与 Outline 在本机运行并热更新。ExUI 使用本机源码构建或监听构建。两种模式保持相同的外部路由与身份语义，开发配置仅改变代理上游、挂载和热更新连接方式。

模式切换前停止原模式写入者，不能同时运行两个实例竞争同一套本地数据。新环境缺少源码、构建产物或配置时应给出具体补齐步骤，不静默退回其他包或数据库。

### 数据与初始化

- 新建此集成专属的 Outline/Hydra 数据库或容器卷，不通过删除旧安装实现“全新初始化”。Website 现有数据不重置。
- 初次 PostgreSQL 数据库创建由显式环境初始化承担；各服务 migration 独立运行，应用日常启动只校验就绪状态。
- 使用持久卷保存数据库、头像和 Outline 附件；普通停止与重启不能删除数据。
- 已有 Website 开发库继续使用或复制到集成环境需在执行前核对目标，不把模式配置视为迁移或删除现有数据的授权。
- 配置示例不包含凭据，镜像构建不复制本机 `.env.local`。运行时秘密由本机配置注入。

## 3. 仓库组织与本地 ExUI

Outline 目标位置为 `apps/outline/`。Website 跟踪 submodule 提交，Outline 内部修改由其仓库管理；整体可复现版本由 Website 提交和 Outline 引用共同确定。接入时保留当前 Outline 工作目录的未提交修改，不用搬移或覆盖方式清理原目录。具体远程地址与接入提交须在实施前核对。

`pnpm-workspace.yaml` 当前包含 `apps/*`，必须显式排除 `apps/outline`。Website 根目录的构建、类型检查、测试与格式化应分别调度 Outline 自身命令，不能让 pnpm 接管 Outline 依赖或让全局文件扫描误入子仓库。

Website 保留本地 `link:`，Outline 保留 `portal:`；新目录下重新计算链接位置。根配置提供本地 ExUI 源码位置，安装与启动前核验链接目标和所需 dist。ExUI 修改先构建，再由消费者加载；不承诺跨仓库源码修改天然触发热更新。

完整容器构建使用额外构建上下文传入 ExUI 源码，在 Linux 构建阶段安装依赖并生成产物，不能复制 Windows 的 node_modules。构建中的目录布局要使 link/portal 与包内依赖正确解析，最终运行镜像也不能留下指向不存在目录的链接。具体目录映射与锁文件规则由环境 RFC 给出。

Docker Compose 提供 `additional_contexts` 能力，但构建器支持情况须由目标环境验证，见 [Compose 构建规范](https://docs.docker.com/reference/compose-file/build/#additional_contexts)。本地 ExUI 会持续变化，因此当前复现记录必须包含其提交和未提交变更状态，不能宣称只凭 Website 提交即可恢复完全相同产物。

## 4. 对外路径契约

Website 使用网站根路径及既有 `/api`。Outline 页面、API、静态资源、附件、认证回调、公开链接、站点地图和实时连接均位于 `/docs` 命名空间内。`/docs` 的页面与深链接由 Outline 处理，不由 Website SPA 吞掉。

Hydra 使用固定的公开 issuer；同一运行环境中，浏览器、宿主机进程和容器都必须能访问该 issuer 声明的地址。内部上游地址不得替代 ID Token 的 issuer。Hydra 的具体公共路径/本地域名由 RFC 依据选定版本验证后确定；文档浏览仍固定同域 `/docs`，不改成文档子域名。

子路径适配包括：

- Router/history basename、服务端生成 URL、重定向及登录后原路径恢复。
- API base、静态资源前缀、动态导入、编辑器附件、图片代理和下载地址。
- 普通事件 WebSocket、编辑协作连接以及开发 HMR。
- Service Worker URL、scope 与缓存键；不得接管 Website 页面或缓存私有文档为公共响应。
- Cookie 名称、Path 和清理范围；不能碰撞 Website/Hydra 会话。
- 搜索结果、嵌入链接、canonical、站点地图及公开文档跳转。

仅在代理中剥离 `/docs` 不能作为完成标准。登录期间允许跳转 Website/Hydra，认证完成后返回原 `/docs` 文档；外部 return URL 必须校验，不能形成任意重定向。

## 5. 统一身份与通用应用接入

### 选择与替代方案

采用自托管 Ory Hydra，将终端用户认证委托给 Website。Hydra 官方明确支持接入既有用户数据库与自定义登录、授权确认 UI，见 [登录与授权流程](https://www.ory.com/docs/oauth2-oidc/custom-login-consent/flow)。Website 通过服务端适配完成 challenge 接受/拒绝，浏览器不直连 Hydra 管理接口。

Keycloak 也可通过外部 User Storage SPI 集成账号，见 [官方开发指南](https://www.keycloak.org/docs/latest/server_development/index.html#_user-storage-spi)。本期保留 Website 现有邀请注册与账号事实，因此不选择迁移身份所有权或开发这套用户存储适配。不选择 Website 自建完整 OIDC 协议服务。

### 登录流程

1. 访客访问 `/docs` 可直接看公开目录；点击登录或访问需要身份的入口时，Outline 发起 OIDC Authorization Code 流程。
2. Hydra 委托 Website 登录适配页面验证身份。已存在本站会话时，通过生成 Client 向 Server 验证；没有有效会话时复用 Website 登录界面。
3. Server 验证 challenge、客户端、会话与账号状态，将稳定账号 ID 作为 subject。Hydra 的历史登录状态或 skip 提示不能代替 Website 当前状态核验。
4. 可信客户端仅获得登记时预先批准的基础身份范围。未经批准的 scope、未知客户端或非法回调拒绝，不默认扩大授权。
5. Outline 完成回调并验证协议响应，绑定固定 issuer 与 sub。必须验证 state、签名、issuer、audience、有效期及适用的 nonce/PKCE，不能将 JWT decode 视为验证。
6. 在已初始化的唯一工作区内幂等创建或读取用户，关联当前浏览器会话组，更新资料并返回原文档。

Website 现有 localStorage Bearer 不会因浏览器跳转自动发送；登录适配必须通过现有前端和受控 Server operation 验证它。其原始 token 不通过 URL、OIDC claims 或 Outline 转发。是否调整本站会话传输形式是 RFC 的独立决策，不能隐式改动现有登录 Contract。

### 稳定关联和客户端边界

- Outline 以 issuer/sub 唯一关联 Website 用户；并发首次登录只能产生一个关联用户。邮箱变化不得生成第二用户，邮箱相同也不得绕过稳定关联自动合并。
- Website 昵称、头像为唯一来源，登录和后续身份复核时同步；资料更新不得覆盖 Outline 文档授权。Outline 的独立修改入口和服务端绕过路径均关闭。
- 初期客户端登记由受控配置或 CLI 完成；每个应用有独立 client ID、回调白名单、scope 和适用的凭据。
- 本期验收 Outline；用第二个最小测试客户端证明通用接入边界，不扩展成第二套正式业务应用。
- 通用 OIDC 接入不自动保证停用与实时撤销。后续应用若要求同等保证，必须实现会话核验与撤销协议。

## 6. 会话与账号生命周期

### 会话组

设计中“当前浏览器”指同一浏览器配置文件内共享的 Website 会话及其关联的 Hydra/Outline 会话。不同设备或独立浏览器配置文件分别关联。关联由服务端建立并持久化，不能只依赖浏览器存储，也不能仅以用户 ID 代替会话标识。

每个 Outline 会话及其协作连接需要可核验的 Website 会话关联。令牌过期、撤销、账号停用、切换账号或重新登录时，不得让旧关联继承新会话的有效性。退出允许清理当前浏览器多标签页状态，不撤销其他设备有效会话。

### 退出、过期与停用

- Website 或 Outline 发起退出时，以 Website 会话组撤销提交为权威生效点，再传播到 Hydra 和 Outline。
- Website 会话过期后，关联 Outline 会话不得单独延长；Hydra 残留登录状态不得静默恢复已失效的 Website 会话。
- 停用是账号级操作，拒绝该账号所有会话；普通退出是会话组级操作，不能使用按 subject 全量撤销替代。
- Hydra/Outline 清理失败时保留可重试状态，不能把权威会话恢复为有效。协议会话的精确撤销粒度、浏览器退出跳转和重试顺序由 RFC 验证。
- 本期需补齐受控的账号停用能力供验收，不额外扩展完整账号管理后台。

Hydra 提供 OIDC logout 流程，见 [官方退出说明](https://www.ory.com/docs/oauth2-oidc/oidc-logout)。它不能独自证明本项目的当前浏览器隔离、Website Bearer 撤销和 Outline 实时连接撤销均已满足。

### 请求与实时连接

每次受保护 HTTP 请求和新建实时连接都同步向 Website 核验关联会话与账号状态，不用跨请求的“仍有效”缓存满足此规则。失效按认证失败处理；不可达或超时按依赖不可用处理，不伪装为账号不存在或无限登录重定向。

已建立的协作连接采用即时失效通知加周期复核/有限有效期的授权租约。设计预算建议每 2 秒复核、单次核验超时不超过 1 秒，并保证从最近一次成功核验起的有效期不超过 5 秒；通知丢失、Redis 中断和 Website 网络故障均不能无限延长该有效期。最终参数和执行顺序须证明满足以下标准：

- 退出或停用在 Website 提交后开始的新受保护请求必须拒绝。
- 已有受保护连接从撤销提交起最多 5 秒内停止接收/传播受保护操作并断开；账号停用覆盖所有设备，退出只覆盖对应会话组。
- Website 从不可核验开始最多 5 秒内停止受保护连接操作；此时匿名公开阅读继续由 Outline 本地公开状态判断。
- 超过撤销期限的实时消息不能写入或广播；断线前已经接受的合法修改如何持久化由 RFC 明确，不能在清理连接时丢失已确认写入。
- 重新连接必须重新核验，不能凭旧 JWT、浏览器缓存或残留 Hydra 会话通过。

正在进行且撤销前已通过核验的 HTTP 操作与撤销之间的竞态由身份 RFC 给出提交边界；涉及权限变更、账号关联和会话建立的写入应在提交前复核。不可把“下一次请求”宣传成跨服务原子事务。

私有附件、导出、后台事件连接及用户可创建的替代 token 入口同样纳入核验范围；不需要的独立登录或个人 API token 通道应禁用，避免绕过统一会话。

## 7. 文档可见性、评论与编辑

| 身份 | 阅读 | 评论 | 新建与编辑 | 管理 |
| --- | --- | --- | --- | --- |
| 匿名 | 公开文档集内已发布文档 | 否 | 否 | 否 |
| 普通登录用户 | 公开内容及明确授权的私有内容 | 对有权阅读的文档允许 | 默认否 | 否 |
| 文档集编辑者 | 同上 | 同上 | 仅指定文档集 | 不可创建文档集或改变公开状态 |
| 文档管理员 | 由 Outline 管理规则约束 | 有阅读权时允许 | 按管理授权执行 | 创建文档集、管理授权、改变公开状态 |

新用户加入工作区不等于加入所有私有文档集。产品角色不能未经验证直接映射到 Outline 的 viewer/member/guest 名称；实现必须同时覆盖团队级新建、文档集级新建、无文档集草稿、复制、导入、移动以及已有单文档授权路径。

普通用户不能通过新建无归属草稿绕过限制。编辑者将文档移动、复制到其他文档集时必须具备目标集权限；移入公开集的已发布文档将受目标集公开规则约束。文档集编辑权限不授予改变匿名公开状态的能力。

### 发布与公开目录

- `/docs` 匿名入口展示公开文档集目录和登录入口，不展示私有文档集名称、数量或不可见内容摘要。
- 公开以整个文档集为单位，已发布文档及未来新发布文档均公开；草稿不因父级公开而公开。
- 编辑者可以直接发布、修改获授权文档，不增加审批；修改已发布内容会影响公开阅读。
- 关闭单篇独立公开、分享 token 公共访问及相应服务端操作。集合级公开可复用 Outline Share 机制，但只允许文档管理员操作，且必须覆盖所有旁路。
- 公开目录、公开全文检索、站点地图和 canonical 只包含可公开内容。撤销公开后新请求不再返回内容，相关缓存失效；不承诺收回访问者已经下载的内容或外部搜索引擎已有副本。
- 附件、内部链接预览、历史版本、导出和嵌入内容单独检查授权。匿名默认不开放历史版本，不能通过已发布页面引用泄露草稿或私有附件。
- 登录用户评论不要求编辑权限。团队/文档集评论配置不得使已确认的“有阅读权即可评论”静默失效；已删除、归档等非活动内容保留相应状态限制。

## 8. 首次工作区与管理员

显式初始化命令接收已有且有效的 Website 账号 ID，创建唯一工作区和固定身份提供方关联，赋予该账号首个文档管理员身份。管理员实际账号在执行初始化时提供，不写死于代码或示例秘密中。

初始化可重试：已存在相同绑定时返回已有结果，冲突时明确失败，不悄悄更换管理员或再建工作区。数据库唯一约束和事务保证并发初始化/首次访问不会产生多个工作区或用户。

未完成初始化时普通用户不能触发 Outline 的“首个用户自动成为管理员”路径；系统返回明确的未就绪状态。后续文档管理员由 Outline 显式授予，Website 社区身份组不自动同步为文档管理身份。

## 10. 验收契约

以下是后续实现必须执行的验收，本次文档工作未运行这些用例。完整容器与开发模式均需验证；单元测试、类型检查和构建通过不能替代浏览器与实时连接验收。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| E01 | 新环境启动 | 配置本地 ExUI、初始化和显式迁移后，根目录入口启动整套服务；不读取其他数据库 |
| E02 | 重启与模式切换 | 账号、文档、头像和附件保留；停止旧模式后新模式可运行 |
| E03 | ExUI 联调 | 修改并构建 ExUI 后两应用消费新产物；完整镜像包含同一源码构建结果 |
| E04 | `/docs` 全链路 | 深链接刷新、登录回调、资源、附件、搜索、SW、HMR 和两类 WebSocket 无前缀逃逸 |
| E05 | 首次登录 | Website 已登录无需再次输入密码；并发首次接入只有一个普通用户，无自动管理员 |
| E06 | 身份稳定性 | 修改邮箱、昵称和头像后用户关联不变，资料按核验同步，Outline 无独立修改旁路 |
| E07 | 多客户端 | 第二个最小测试客户端独立登记可登录；错误回调、未知客户端及超额 scope 被拒绝 |
| E08 | 匿名边界 | 公开目录和已发布内容可读可检索；私有名称/数量、草稿、历史和私有附件不可泄露 |
| E09 | 评论与编辑 | 普通用户可评论可读内容但不可新建/编辑；编辑者仅在授权集操作，不能新建集或改变公开状态 |
| E10 | 发布与分享 | 编辑者发布后公开可读；单篇分享 API/UI 无旁路；撤销整集公开后新访问与缓存不能泄露 |
| E11 | 单浏览器退出 | 从任一服务退出，关联请求拒绝且连接最多 5 秒断开；另一设备继续有效；旧 Hydra 状态不能恢复登录 |
| E12 | 账号停用与过期 | 停用覆盖所有设备；下一次受保护请求拒绝，连接最多 5 秒失效；会话过期不能续接 |
| E13 | 故障与通知丢失 | Website 不可达、核验超时、失效消息丢失时受保护操作失败，连接不超过 5 秒；公开阅读仍可用 |
| E14 | 初始化与隔离 | 未初始化不可抢管理员；重复/并发初始化幂等或明确冲突；Website 管理员不自动获得 Outline 管理权 |
| E15 | 协作一致性 | 双浏览器编辑同步；只读连接不可写；撤销后的消息拒绝，已确认合法修改保持一致 |
| E16 | 协议与替代入口 | 无效 state/令牌/issuer/audience 被拒绝；旧会话、个人 token、直接附件与事件连接不能绕过核验 |

测量 5 秒以 Website 撤销提交或依赖失效时间为起点，记录服务端最后接受操作、断开和重连拒绝时间；不能只观察按钮消失。按用例报告 PASS、FAIL、NOT_EXECUTED，未执行不算通过。

Website API 变更遵循 `api/openapi.yaml` → `pnpm api:lint` → `pnpm api:generate` → handler/client/tests 的顺序。Contract 测试同时验证 HTTP 与已登记 handler 原始输出。数据库测试继续用隔离容器。Outline 使用其自身测试约定与定向用例，不混用两个包管理器。

## 11. RFC 分解、证据缺口与实施顺序

本规格覆盖一个完整集成目标，按可独立实现和验证的边界建议拆成三份 RFC，均保留在 `.notes/archive/docs-integration/rfcs/`：

1. **环境与子路径**：submodule、workspace 排除、本地 ExUI、Dockerfile/Compose、存储与显式初始化命令、完整 `/docs` 路径矩阵。
2. **统一身份与生命周期**：Hydra 版本与配置、Website Contract/数据模型、登录授权适配、稳定关联、会话组、退出停用、通知与 5 秒约束。
3. **Outline 文档授权与公开入口**：工作区管理员初始化、权限映射、公开目录/检索、分享限制、附件/缓存和跨模块验收。

先完成环境和路径验证，再接入最小登录闭环，随后完成会话撤销与权限公开能力，最后执行两种模式全矩阵。局部闭环通过不能宣称整体集成完成。

以下项目是 RFC 必须解决的工程证据缺口，不改变已确认产品规则，也不表示功能已验证：

| 项目 | RFC 必须产出的结果 |
| --- | --- |
| Hydra 自托管版本 | 锁定镜像版本/摘要，验证所用管理 API、退出粒度、公开 issuer 路由及客户端配置，不直接照搬云服务 Console 操作 |
| Outline OIDC 校验 | 检查完整库调用链，给出签名/issuer/audience/nonce/PKCE 校验位置和负向测试，决定必要补强 |
| 会话组映射 | 具体唯一约束、token 关联、当前浏览器退出顺序、失效重试与故障恢复；不按 subject 误撤其他设备 |
| Website 状态接口 | 明确停用能力、受控调用方、每请求核验 Contract、资料版本及事务边界；更新数据模型后再实现 |
| 5 秒约束 | 定时复核预算、请求超时、过期检查位置、消息接收与持久化边界，以及丢通知/网络隔离实测 |
| 公开模型与角色 | 明确 collection Share、角色、成员权限的实际映射，补团队级与集级规则交叉测试；核查匿名附件与缓存 |
| 本地构建 | 确定 ExUI 链接目录布局、Linux 安装、运行镜像依赖闭包、Windows 热更新与 Docker 到宿主机寻址 |
| 源码接入 | 确认 Outline fork 远程与引用提交，保留现有修改，不能用未经提交的本地状态冒充可克隆版本 |

后续 RFC 不得用“由部署解决”“以后支持”等措辞跳过上述验收条件。若证明既定方案无法满足要求，应带具体证据返回设计评审，而不是静默降低标准。
