# About Media：电影章节设计

## 决策与范围

用户已选择视觉伴侣的 B「电影章节」，并明确音乐与影像不能处于同一行。页面采用大画面开场、音乐、影像三个纵向章节。用户随后明确跳过 RFC、直接开始开发；本文件记录开发依据。

范围为 `/aboutus/media` 的视觉、播放列表嵌入及视频外链展示。沿用 About 路由、栏目导航、内容编译与阅读位置流程。无 HTTP Contract、Server、数据库或部署变更；不增加站内视频播放器、筛选、搜索、轮播或音乐 SDK。

本模块固定为 `.notes/about-media/`，设计位于 `specs/`。用户明确取消 RFC 交接，直接开发；提交与部署仍需单独授权。

## 已确认素材

背景视频：

`https://d2cstorage-a.akamaihd.net/atl/charlixcxreskinghyu/CleanShotDesktop-hbbdbfdf.mp4`

当前浏览器读取到 1792 × 1080、约 6.97 秒的黑白街景视频。页面使用此地址，不把它作为影像目录中的作品。

Apple Music 播放列表：

`https://embed.music.apple.com/us/playlist/what-are-we-loading/pl.u-e98lM6ESaWXyEK`

使用用户最新提供的原生 iframe，保留 `allow="autoplay *; encrypted-media *;"` 和以下 sandbox 权限：

`allow-forms allow-popups allow-same-origin allow-scripts allow-storage-access-by-user-activation allow-top-navigation-by-user-activation`

iframe 桌面展示高度为 640px，手机保留原生 450px，宽度为父容器的 100%，最大 800px，背景透明，无外框，添加可读的 `title`。原始歌曲地址已被这个播放列表地址取代，不进入最终页面。页面不追加播放器下方的来源文字或外部打开链接。

浏览器已显示歌单 `what are we loading` 及歌曲列表，验证的是嵌入加载和布局，不是音乐播放、订阅或账号登录能力。

## 页面章节

### 1. 大画面开场

主站头部和 About 栏目导航继续使用既有组件。Media 内容背景横向铺开，正文保持站点内容最大宽度。深色呈现只作用于 Media，不改变全站主题设置或其他页面。

开场保留标题「音乐与影像」及简短引言，采用 B 草图的大字号、左对齐与宽留白。桌面上开场至少占据顶栏和栏目导航下的剩余首屏高度；短视口、手机和放大页面允许内容自然撑高，不裁切标题。自然纵向滚动，不劫持滚轮、不强制整屏翻页。

背景视频覆盖 Media 内容区域，按 `object-fit: cover` 裁切；滚动时仍作为页面背景可见。开场遮罩较轻，进入内容章节后逐渐加深，突出前景文字与播放器。播放器保留 Apple 原生颜色，不对 iframe 内部做主题覆盖。

首屏提供始终可操作的「暂停背景 / 播放背景」按钮，状态与实际视频播放结果同步。按钮不会与音乐播放器联动。

### 2. 音乐章节

标题「我们的歌单」，配一段短说明。桌面上章节内部可以左侧说明、右侧 iframe；这个排列只属于音乐章节，影像章节始终在它的下方。手机上说明在先、播放器在后。

播放器桌面展示高度为 640px，手机保留原生 450px 高度，独立占位保证加载过程中布局稳定。播放器下方不追加来源文字或外部打开链接。播放、歌单内部滚动、登录及订阅由 Apple 提供，页面不自动触发音乐播放，不复制歌曲列表，不模拟播放器。

iframe 可在章节接近视口时加载。跨域 iframe 无法可靠推断内部网络和播放状态，不用 `onload` 宣称播放成功，不假设父页面能检测全部错误。原生控件由 Apple 管理。

### 3. 影像章节

标题「影像记录」，使用 16:9 封面卡片、视频标题、简短说明和外链箭头。桌面三列、中等宽度两列、手机一列；按现有公开条目顺序显示全部视频，超过三项自然换行，不截断目录。

每个有来源的视频是一个可键盘操作的外链，在新标签页打开并隔离 opener；不打开播放弹窗、不嵌入各平台播放器。保留 `media-{id}` 锚点和既有相关内容入口。

没有封面时显示同尺寸普通占位；没有外链时显示「来源待补充」，不制造可播放入口。真实视频标题、地址与封面尚未提供，继续使用明确的整理中或现有占位状态。视觉伴侣中的示意作品不会被导入为真实资料。

## 播放、降级与可访问性

- 背景设置 `autoplay`、`muted`、`loop`、`playsInline`；背景始终静音，不提供背景声音开关。
- 自动播放被浏览器拒绝时保留深色背景和正文，允许用户通过播放按钮再尝试；按钮状态不能提前显示为正在播放。
- 背景请求失败时使用稳定深色背景，歌单与视频外链仍可使用；不因装饰素材失败阻塞页面。
- 系统要求减少动态效果时默认不播放背景，使用静态深色底；仍可由用户明确选择播放。手动暂停保持到离开 Media，恢复前台不能覆盖用户的暂停选择。
- 标签页进入后台时暂停背景；回到前台只恢复原本应播放的背景。离开路由释放视频、监听和观察器；其他页面不持续加载或播放这段视频。
- 标题层级、导航、焦点指示与正常阅读顺序保持完整。背景不进入辅助技术阅读顺序；背景按钮有清楚标签及可见焦点。
- 保留路由后退阅读位置、页面标题和 h1 入口焦点；直接访问视频锚点时，定位不被字幕、背景或章节布局覆盖。

## 内容与组件边界

当前 `MediaList.tsx` 将音乐、视频混在筛选卡片中；固定 Media 页面正文位于 `apps/web/content/about/media/index.mdx`，目录位于 `apps/web/content/about/media/items.yaml`。构建 schema 和公开投影分别位于 `apps/web/build/about/schema.ts` 与 `apps/web/build/about/definition.ts`。

设计采用 Media 专属页面组合，拆分背景生命周期、音乐嵌入和影像目录三个职责；样式位于 Media 的 CSS Module，使用 ExUI 公共 token 和 Lucide 图标。复用既有 MDX 加载、错误恢复和内容注册表，不引入第二份内容加载系统。

文案继续由 Media MDX 维护；背景地址及唯一播放列表地址作为 Media 内容配置的明确字段，由当前编译链校验后公开。实现采用独立 `aboutMediaPage` 集合与 `kind: media`：frontmatter 配置 backgroundVideoUrl、playlist 的 embedUrl/title/description，以及 videos 的 title/description。视频目录只接受 type: video，继续使用 id、顺序、draft、cover、sourceUrl 和 related 字段。

不将用户粘贴的任意 iframe HTML直接注入正文：UI 持有已确认 iframe 属性，内容只配置受控 Apple Music 播放列表 URL。维持草稿过滤、图片资源边界和作者链接检查。背景使用公开 HTTPS 地址，不新增服务器下载、转码或平台抓取。

## 验收要求

实现阶段执行对应 Web 类型检查、内容检查、相关行为测试与 Web 构建，命令以当前仓库脚本为准。此设计阶段不宣称这些实现检查已通过。

行为验证覆盖播放器地址与属性、仅视频进入外链目录、草稿过滤、缺失封面与来源、视频锚点、背景暂停与恢复、自动播放拒绝、减少动态效果及路由卸载。

真实浏览器分别检查桌面、390px 手机宽度和 200% 缩放：音乐与影像始终上下排列；播放器桌面展示为 640px 高、最大 800px 宽，手机为 450px 高且无横向页面溢出；所有视频可达；键盘可操作背景控制及外链；背景可循环、可暂停且不产生声音。检查视频或 Apple 域名请求受阻时的正文与影像外链，并检查直接访问锚点、离开后返回和其他页面无背景视频残留。

自动检查、真实浏览器效果与第三方播放能力分别报告。本阶段不部署上线。

## 依据与风险

用户选择 B，并提供最终播放列表嵌入；视觉伴侣已验证真实 iframe 加载及上下分区。参考 Charli 的简洁入口和 Lusion 的大画面、内容章节节奏，不照搬它们的交互系统：

- https://www.charlixcx.com/cr-homepage
- https://lusion.co/
- https://support.apple.com/guide/music-web/share-music-apdm0783785d/web

背景 CDN 和 Apple 嵌入依赖第三方可用性；背景失败时使用深色背景降级，Apple 嵌入失败不阻塞其他正文与影像外链。视频体积、移动网络表现、真实设备自动播放及 Apple 账号播放能力仍需实现后的浏览器验证。真实影像资料尚缺，影响内容完整度，不阻塞页面设计。
