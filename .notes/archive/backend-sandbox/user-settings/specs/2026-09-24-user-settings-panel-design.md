# 用户设置面板设计

- 状态：已确认
- 日期：2026-09-24
- 模块：`.notes/archive/backend-sandbox/user-settings/`

## 目标与范围

为已登录用户提供一个以 Modal 为主要入口的设置面板。面板采用 ChatGPT App 式的左侧分类导航、右侧内容区，并在内容区用分组标题和平面设置行组织设置。设置主体不依赖 Modal 或路由容器，以便现有 `/account/profile` 深链接和未来独立设置页使用同一套内容。

首版只有三个分类：

| 分类 | 设置 |
| --- | --- |
| 通用 | 网站主题：浅色、深色、跟随系统。 |
| 个人资料 | 居中展示 Glass 头像及可编辑用户名；裁剪并上传、替换或移除 512×512 头像。 |
| 账号 | 查看只读登录邮箱；修改或清空 QQ，以及手填、修改或清空 FiveM ID。 |

退出登录是桌面侧栏底部的独立操作；手机端在顶部分类菜单中提供，在任意分类中可用。

个人资料中的用户名沿用 `nickname` 字段；账号“关联信息”中的 QQ 沿用 `qq`，FiveM ID 沿用 `fivemId` 字段及 `fivem:数字ID` 格式。FiveM ID 是用户声明，必须标注“未验证”，不用于身份认证、社区组归属或权限判断。QQ 和 FiveM ID 移入账号分类只是界面分组调整，不改变现有业务语义和公开资料属性。首版不增加邮箱修改、密码修改、通知、隐私控制、FiveM 身份验证或新 HTTP operation。

## 已有基础与设计依据

- 当前 `api/openapi.yaml` 已声明本人资料读取、局部更新、头像上传及公开头像读取的 operation；网页现有 `ProfilePage` 和共享 `ProfileEditor` 已调用这些能力。
- `ThemeProvider` 位于整个路由树之上，现有 `ThemeToggle` 已提供浅色、深色、跟随系统三个选项。
- 登录用户菜单已有“个人资料”入口、未接线的“设置”项和退出登录项；`/account/profile` 已是可访问的页面路径。
- [用户基础资料设计](../../../user-profile/specs/2026-09-23-user-profile-design.md)与 [数据模型](../../../../../.ai/databases/data-model.md)明确 FiveM ID 未验证且不授予身份或权限。本设置面板不得暗示已验证绑定。

## 界面与导航

首版从已登录用户菜单打开设置 Modal：“设置”默认选中“通用”，“个人资料”默认选中“个人资料”。左侧固定显示“个人资料 / 通用 / 账号”，退出登录以透明背景、红色文字位于菜单底部；右侧以当前分类标题作为显著的 Title，下方显示分组标题和平面设置行。设置 Modal 不显示额外的顶部标题或说明，但保留可访问名称。每个设置行左侧只有一个 Label，可选说明位于 Label 下方；右侧展示当前值或操作控件。

桌面 Modal 宽度使用 `clamp(42rem, 72vw, 64rem)`，高度使用 `clamp(32rem, 72dvh, 48rem)`，并受视口四周 2rem 留白约束。视口宽度不超过 38rem 或高度不超过 34rem 时，Modal 填满可见视口。手机端在顶部分类菜单中提供分类切换和退出登录；内容区超出可用高度时独立纵向滚动，设置行上下排列。关闭按钮始终可见。

现有 `/account/profile` 路径继续可用。该路径以页面容器承载同一个设置主体，默认选中“个人资料”；在该页面切换分类不新增路由或修改 URL。页面和 Modal 使用同样的字段分组、编辑动作与状态反馈。Modal 的关闭按钮和 Escape 只关闭设置容器，返回触发它的用户菜单入口；独立页没有关闭按钮。

通用页的“外观”分组在“网站主题”设置行右侧使用 ExUI Select，提供浅色、深色、跟随系统三个选项，选择后立即应用现有主题状态。顶栏不再显示主题切换，主题状态仍由 ExUI `ThemeProvider` 管理。

个人资料页将 Glass 头像独立居中展示，不放在设置行中；没有头像时显示更大的用户名首字。头像下方显示可点击的用户名，点击打开单项编辑对话框；不再显示用户名设置行。点击头像打开上传对话框，可选图或移除现有头像；选图后打开 `react-easy-crop` 的 1:1 裁剪对话框，可拖动和缩放图片，确认前预览最终正方形范围；取消不上传。头像源文件仍只接受现有 PNG、JPEG、WebP 格式和 2 MiB 大小限制；用户名沿用现有校验规则。对话框关闭前不将未保存的输入写入展示值。

账号页分为“登录信息”“关联信息”两个分组。登录邮箱设置行右侧展示完整的只读邮箱，左侧说明当前不可修改；关联信息中按 QQ、FiveM ID 排列，右侧当前值或“未设置”是透明背景、无描边且有左右留白的可点击按钮，点击后单项编辑或清空。FiveM ID 设置行左侧说明“未验证”，不得把手填 FiveM ID 表示为第三方账号已授权或已核验。设置行 Label 字号大于说明文字。

## 组件与数据边界

采用共享设置主体加薄容器的结构：

```text
apps/web
  用户菜单入口 / 现有 /account/profile 路由
  现有 AuthContext：登录态、会话、顶栏资料与退出登录
  settingsConfig（Valtio）：设置资料缓存、请求状态与主题投影
  设置控制层：GET/PATCH/头像操作、主题适配、资料同步
       ↓ 数据与回调
packages/components
  SettingsPanel：分类导航、分组标题与设置行
  单项编辑对话框 / 头像裁剪对话框与操作表单
  ContentAreaState：整个内容区的加载骨架、错误消息与重试按钮
       ↑
  Modal 容器或页面容器
```

`packages/components` 只接收当前资料、主题、提交状态及操作回调，不调用 API、不读 token、不依赖 Valtio、不定义路由。Modal 容器负责隐藏但可访问的名称、焦点约束和关闭；页面容器负责页面级标题与宽度。两者不复制设置行的业务展示。`apps/web` 经 `@workspace/api-client` 调用 Contract 中已有的 operation。现有 `AuthContext` 保持原有职责和接口，顶栏继续从它读取用户名与头像；设置控制层通过其现有方法处理资料刷新和会话失效。现有 `ProfilePage` 中的资料请求逻辑应提取为共用的设置控制逻辑，避免 Modal 与页面容器各自维护一套请求与错误处理。

表单遵守 `.ai/rules/frontend-forms.md`：React Hook Form 管理字段、错误与提交状态，Zod 定义规则并接入 resolver，ExUI 提供输入、错误和 Dialog 控件。当前 `ProfileEditor` 的用户名、QQ、FiveM ID 和头像文件校验规则应被复用或提取，不能在新面板中产生第二套不一致的校验。裁剪位置与缩放值是裁剪对话框的临时交互状态，不进入 `settingsConfig`。CSS Modules 仅使用 ExUI token；不在共享包重复导入 ExUI 样式。

## 全局设置状态与整页内容加载

考虑后续设置项会增加，首版在 `apps/web` 建立一个全局 Valtio `settingsConfig` 读取模型。它包含通用设置的当前主题投影，以及本人设置资料 snapshot（供个人资料和账号两页读取）与该 snapshot 的 `idle` / `loading` / `ready` / `error` 请求状态。新增设置分类时可向该模型增加有明确来源的切片。`apps/web` 的适配层用 `useSnapshot` 读取并把所需值作为 props 传给共享 UI，写入必须经过 `apps/web` 的设置动作；编辑框草稿、当前选中的分类和内层对话框开关仍属于各容器的局部状态，不进入全局对象。全局资料只保存在当前浏览器内存中，不单独持久化邮箱、QQ 或 FiveM ID。

`settingsConfig` 只服务于设置内容，不接管或改写现有 `AuthContext`。登录态恢复、token 生命周期、顶栏用户名与头像仍由 `AuthContext` 按当前方式管理；它不从 Valtio 读取资料，现有接口和行为保持不变。`GET /auth/me` 的服务器响应是本人资料的事实来源：设置 Modal 与 `/account/profile` 页面共用 `settingsConfig` 中的设置资料缓存；保存成功时先以服务器返回的完整 snapshot 更新该缓存，再调用现有 `auth.refreshProfile()` 更新 `AuthContext` 的顶栏资料。如果这次顶栏刷新失败，保留已成功保存的设置结果，在设置面板提示顶栏刷新失败，不回滚服务器已保存的数据。设置缓存绑定发起请求时读取的 token；token 改变、`AuthContext` 转为 `anonymous` 或会话失效时清空，临时 `unavailable` 且 token 未变时保留缓存以支持重试。退出成功会由现有页面刷新清空内存中的缓存。设置请求在写入前核对 token 和请求代次，防止迟到响应覆盖新状态。再次打开设置时仍刷新资料，避免长期使用旧 snapshot。

ExUI 的 `ThemeProvider` 继续负责主题持久化、跨标签同步和页面类名，遵守已接受的主题来源决策。`settingsConfig.general.theme` 是其**只读投影**：应用级适配器从 `useTheme` 同步当前值，所有修改主题的入口仍调用 `setTheme`，随后由适配器更新投影。不要从 Valtio 反向写入 `ThemeProvider`，也不要建立第二份主题持久化。设置页与页面其他主题消费方因此读到同一主题。

新增可复用的 `ContentAreaState` 展示组件，放在 `packages/components`。它占据宿主提供的**整个内容区域**，而非单个字段或设置行；只接收 `loading`、`error`、`ready` 三种状态、整页骨架内容、错误文案、重试回调与成功内容，不发请求、不保存业务数据。加载态使用 ExUI 已导出的 `Skeleton`，设置面板提供匹配分类标题与设置行的骨架；未来文档内容页可传入匹配标题、目录和正文的骨架。加载态提供可访问的“正在加载”状态文本；错误态替换整个内容区域，使用 ExUI 的错误提示和“重试”按钮；成功态渲染整块内容。错误态必须结束骨架动画，重试时才重新进入加载态。通用页主题不依赖资料请求，保持可用。

## 交互与状态

打开设置时“通用”可立即使用。首次进入“个人资料”或“账号”时，读取全局资料切片；若尚无可用 snapshot，则通过已有 `GET /auth/me` 加载。Modal 关闭后再次打开会刷新资料，避免显示旧值；刷新期间整个当前内容区通过 `ContentAreaState` 显示分类标题与设置行骨架，失败时以整块错误与重试替换骨架，不影响通用页的主题设置。同一次设置会话的个人资料和账号分类共用同一 snapshot 和请求状态。

用户名、QQ 和 FiveM ID 分别通过已有 `PATCH /auth/me` 提交局部更新。用户名不可清空；QQ 和 FiveM ID 可按现有 Contract 的 `null` 语义清空。头像选图后先完成 1:1 裁剪，前端按裁剪坐标把图像绘制到 512×512 Canvas，并将导出的图片按实际 `mediaType` 经现有 `POST /auth/me/avatar` 上传；如果浏览器不能导出 WebP，可使用现有 Contract 接受的 JPEG 或 PNG，服务端仍统一存为 WebP。上传前核对导出结果的格式与 2 MiB 限制，导出或上传失败时保留裁剪对话框供重试。移除头像继续使用现有 `PATCH /auth/me`。每次成功后用返回的完整 snapshot 更新 `settingsConfig`，并调用现有 `auth.refreshProfile()` 同步顶栏头像和名称；设置数据与 AuthContext 仍由各自原有边界读取。请求进行中禁用当前动作的重复提交；失败时保留编辑框与输入，显示安全的错误消息，允许重试。

服务端继续使用现有 Sharp 处理所有头像请求，包括绕过前端裁剪的直接 API 请求。将当前 `fit: 'inside'`、`withoutEnlargement: true` 的缩放策略调整为固定 512×512 正方形输出：对非正方形输入居中裁剪，较小图片按需放大，最终编码为现有 WebP 格式；原有输入格式、输入大小、像素上限和输出字节上限校验继续有效。这样最终存储尺寸由服务端保证，而不依赖浏览器提交的图片尺寸。头像响应字段与 HTTP operation 不变。

如果资料请求返回 `SESSION_INVALID`，沿用现有匹配 token 的会话失效处理，关闭设置并更新登录状态。关闭 Modal 或切换分类时，不得让已结束会话中的迟到请求覆盖新的资料状态。临时网络失败不清除 token；重试只重发必要请求。

退出登录直接调用现有 `auth.logout()`，由 `AuthContext` 执行既有 `POST /auth/logout`、token 清理和成功后的页面刷新。设置层在点击后标记本次操作进行中并禁用重复提交；若 `AuthContext` 转为 `unavailable`，解除进行中状态，在仍打开的设置 Modal 内显示其错误消息和重试操作；若转为 `anonymous`，关闭设置；成功后的既有页面刷新结束当前界面。设置层不复制退出请求，也不修改 `AuthContext.logout` 的接口或内部行为。

编辑对话框位于设置 Modal 内时，应保证键盘焦点留在最上层对话框；Escape 先关闭编辑对话框，再关闭外层设置 Modal。关闭编辑框后焦点返回对应设置行。页面容器下同一编辑框应有一致行为。

## 验收与验证

- 已登录用户从“设置”和“个人资料”菜单项进入同一 Modal，初始分类分别正确；匿名用户不会看到设置入口。
- 三个分类、平面设置行和窄屏导航可用；桌面尺寸受上下限约束，手机全屏时内容可滚动、关闭与顶部菜单中的退出操作可达；主题切换立即生效。
- 用户名、QQ、FiveM ID 分别提交且只修改目标字段；可清空字段正确清空，非法输入显示字段错误。FiveM ID 始终标注未验证。
- 选图后可在裁剪对话框中拖动、缩放和预览，取消不上传；上传、替换和移除后面板及顶栏展示一致。前端裁剪上传和直接 API 上传所得头像均为 512×512 WebP；邮箱只读，退出登录成功与失败路径均可观察。
- 资料加载失败可重试；保存失败保留输入；会话失效和关闭后的迟到响应不会污染新状态。
- Valtio 设置资料缓存在保存、重开设置、跨账号切换、会话失效和退出时保持一致；`AuthContext` 原有登录与顶栏行为保持，成功保存后仍通过现有 `refreshProfile()` 同步顶栏；主题投影跟随 ExUI 主题及跨标签变化，不发生双向写入循环。
- 通用 `ContentAreaState` 分别验证整块内容区域的加载骨架、错误与重试、成功内容及可访问状态；设置 Modal 与页面容器使用同一状态展示，文档页将来可提供自己的整页骨架。
- Modal、内部编辑框和页面容器通过键盘、焦点返回及 Escape 检查；在桌面和窄屏真实浏览器中检查布局。
- 执行仓库的 `pnpm typecheck`、`pnpm test`、`pnpm build`。本设计不改 Contract，因此无需生成新 API Client 或声明新增服务端能力；若实施时发现必须变更 Contract，先回到 Contract 评审并遵守 `AGENTS.md` 的固定顺序。

## 风险与限制

设置 Modal 内的编辑和头像裁剪 Dialog 需验证焦点与 Escape 顺序。`react-easy-crop` 要求裁剪容器尺寸稳定，头像裁剪 Dialog 不使用改变尺寸的缩放入场动画，并需在浏览器中核对裁剪范围和导出结果。较小源图放大到 512×512 可能模糊，裁剪预览应让用户看到效果。现有 `AuthContext.logout` 不返回完成结果；设置层只能根据其状态变化识别失败，成功路径由原有页面刷新完成，需验证 Modal 在 `unavailable` 状态下仍可显示错误和重试。`settingsConfig` 与 `AuthContext` 分别缓存本人资料的不同用途，保存成功后必须调用现有 `refreshProfile()`，并在会话变化时清空设置缓存；主题投影仅用于统一读取，不能成为第二个写入来源。`/account/profile` 需要与 Modal 共用设置主体，否则 FiveM ID 会在旧页面和新账号页出现不同分组。通用骨架组件应允许按内容提供形状，避免给设置和文档页强加同一套占位尺寸。FiveM ID 仅是手填关联；未来真正的身份验证是独立设计，不由当前字段或界面文案推断。

设计确认后，按仓库要求另行征询用户是否将稳定结论提炼到 `.ai/`。本设计文档归档在 `.notes/archive/backend-sandbox/user-settings/`，不作为新的 API Contract。
