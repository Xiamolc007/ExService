# 双预设整篇替换协议

状态：已通过 grilling 逐项确认，用户以 `go` 授权实施。

## 目标与范围

将完整富文本与 GFM 的整篇替换、接纳回执、历史隔离、会话失效和诊断时序集中到包内私有 module。删除 `useMarkdownEditor` 及兼容类型、别名，迁移仓库内使用者；统一使用 `useTiptapEditor` 与 preset。保留独立转换函数、extensions 工厂及两种内容规则。不处理架构评审的图片归属、JSON 遍历或块目录候选。

## 已确认契约

1. 候选先解析与校验，以真实 Plugin state.apply 回执确认接纳，不能以命令布尔值代替。
2. 拒绝保留正文、选区、Undo/Redo、交互目标和所属异步操作。
3. 成功（包含等价替换）清空 Undo/Redo，取消旧 Emoji、Slash、上传和 Mention；光标到文首，焦点保持原状；通知一次 onChange。
4. 初始化失败锁存并阻止导出，普通编辑不解除；成功显式替换才解除。
5. 新正文接纳、更新的显式操作结果、解绑或销毁使排队旧诊断失效；仅光标移动不失效；连续拒绝仅报告最新诊断，各实例独立。
6. dispatch 及追加事务完成后取正文快照；返回值与 onChange 参数为彼此独立的对象。
7. 回调异常通过浏览器全局错误通道暴露，不进入内容 issues，不改变操作接纳结果；各回调独立执行。
8. 回调可发起下一次替换；内部提交先于通知，通知按操作批次 FIFO 发送，重入操作各自返回自己的快照。

## 结构与选择

采用组合：共享内容会话 module 接受 parse/validate/serialize adapter，持有 Editor 归属、初始化错误、操作回执、诊断序号与通知队列。完整 runtime 保留上传、Mention、位置映射和 IME；GFM 保留粘贴语义。内容门禁复用同一诊断与回执机制，并支持独立 extensions 路径。

只提取事务 helper 会留下接纳与诊断分散；合并两个 runtime 会混合本来不同的交互与内容规则。组合集中共有知识，避免继承基类与新的公开协议。

## 验收与边界

真实 Editor 和统一 Hook 的双预设测试覆盖接纳、拒绝、等价替换、历史、交互失效、初始化恢复、追加事务、回调异常、重入和诊断时序；独立 GFM extensions 保留门禁及粘贴验证。旧 Hook 测试迁移有效行为断言。执行 Tiptap 专项、类型检查、受影响构建及已有服务上的相关浏览器流程。无持久格式变更，无部署；不承诺第三方插件任意抛错后的通用事务回滚。
