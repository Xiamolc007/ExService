# 通用错误面板与注册错误展示设计

日期：2026-10-10。模块：`error-panel`。状态：视觉与行为方向已确认，本文待用户审阅。

## 决策摘要

采用 B 方案，在 `packages/components/` 新增通用 `ErrorPanel`。以柔和背景、细边框和小型错误图标呈现本次操作需要处理的问题；支持多条错误与整个面板的最大高度。标题和可选底部 Action 固定，只有错误列表滚动。

用户已确认 Action 可省略：不传 Action 时，整个底部区域不渲染，包括分隔线、操作提示及其留白。首次接入注册页和注册弹窗，消除同一错误在页面、表单与临时通知中的重复展示。

模块根目录固定为 `.notes/error-panel/`。后续 RFC 位于 `.notes/error-panel/rfcs/`。

## 问题与现有证据

- `apps/web/src/invitations/InvitationRegistrationFlow.tsx` 的 `checkFailure` 同时调用 `setError`、`form.current.setServerErrors` 和 `ExMessage.error`。组件外层还有一个依赖 `error` 的 Alert。
- `packages/components/src/auth/InvitationForms.tsx` 的邮箱表单通过 `root.server` 再渲染 Alert；验证码失败和注册完成失败也存在流程错误与表单错误同时展示的路径。
- `apps/web/src/pages/AuthPage/InvitationRegistrationPage.tsx` 与顶栏注册弹窗共用 `InvitationRegistrationFlow`，因此修复需要同时覆盖两种容器。
- `packages/components/src/ContentAreaState.tsx` 处理加载、错误与正常内容三种页面状态，其错误接口是单条文案加必需重试回调，不承担本次多条错误面板职责。
- 当前错误 envelope 和邀请注册接口不需要改变。通用组件能接收多条 UI 错误，不表示注册 API 已经返回错误数组。

## 范围

本次设计包括 `ErrorPanel` 的共享接口、样式和可访问性，以及注册流程中错误展示的单一归属。注册入口参数错误、邮箱资格检查失败、验证码错误、重发失败与完善账号失败均须保持可见且可恢复。

现有字段校验继续由 React Hook Form 和 Zod 管理，并在所属字段使用 ExUI `FieldError`；不把相同字段文案再次复制到面板。跨字段或流程失败使用面板。同一错误只有一处可见文案，不同时发送同内容的错误通知。

其它页面后续可复用组件，本次不批量改写登录、设置、申请、通知中心或 Outline。保留现有登录跳转、验证码锁定与重发冷却、敏感材料清理及迟到请求保护。不修改 HTTP Contract、数据库、依赖锁文件或运行配置。

## 组件契约

以下是拟新增的 UI 接口；不是服务端 DTO。

```ts
interface ErrorPanelItem {
  id: string
  message: string
  description?: string
}

interface ErrorPanelProps {
  errors: readonly ErrorPanelItem[]
  title?: string
  maxHeight?: number
  action?: ReactElement | null
  id?: string
  className?: string
}
```

`ReactElement` 使用 React 的公开类型。Action 由调用方提供 ExUI Button 或包裹路由链接的控件；组件不注册路由、不调用 API、不解释错误码。

| 输入          | 约定                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `errors`      | 本次结果的完整列表，按传入顺序展示；`id` 在列表中唯一且稳定。不同字段的相同文案仍是不同错误，不按文案去重。            |
| `message`     | 必需的用户可读文案，非空。作为文本渲染，不接受 HTML、堆栈或原始异常对象。                                              |
| `description` | 可选的修正说明；省略时不保留说明占位。                                                                                 |
| `title`       | 可选标题。省略时不渲染标题区；单条不显示数量，多条有标题时在标题区显示数量。                                           |
| `maxHeight`   | 整个面板的像素上限，默认 240；支持 160 px 及以上的有限数值。更小、非正值和非有限值回退默认值，避免标题与操作占满面板。 |
| `action`      | 可选 React 元素。`undefined` 或 `null` 时不渲染整个底部区域；有 Action 时保留固定底部区域。                            |
| `id`          | 可供输入框的 `aria-describedby` 引用面板。                                                                             |

空列表返回 `null`，不留下容器、边框或间距。调用方负责确保条目有效、稳定和唯一；组件不自行累积历史错误。

## 布局与视觉

```text
面板总高度 <= 生效的 maxHeight
┌─────────────────────────────┐
│ 可选：小图标、标题、错误数量 │ 固定
├─────────────────────────────┤
│ 错误文案                    │
│ 可选说明                    │ 可滚动
│ 多条错误之间使用细分隔线    │
├─────────────────────────────┤
│ 可选：Action                │ 固定；没有 Action 时整区移除
└─────────────────────────────┘
```

标题下方不增加单独装饰分隔线；上图分区线仅说明结构。Action 顶部的分隔线随 Action 区域一起出现或移除。

未达到高度上限时自然收缩，不设置固定高度或最小面板高度。单条省略编号，多条使用轻量序号辅助扫描。正文约 13 px、说明约 12 px，按项目排版体系实现；使用小型红色图标表达错误，其余文字使用主题主次文本色，不使用整块鲜红背景。

外观使用 CSS Modules、ExUI 的表面、边框、圆角及文本 token，图标使用 `lucide-react`。基于 ExUI Alert 等现有公开组件组合，不引入另一套表单控件或通知系统；全局样式仍只在应用入口导入。

列表使用 `min-height: 0` 与纵向 overflow，长文案和长连续字符串换行，不省略错误正文。滚动条仅在溢出时出现，滚动到边界不连带滚动弹窗背景。有无标题、有无 Action 均计入整体高度计算，缺少区域时把空间留给列表。

## 错误归属与生命周期

`ErrorPanel` 只接收展示数据，不持有业务错误、提交状态或错误历史。

- Form 错误保留在所属 React Hook Form 实例，流程层只负责请求分支、错误映射和失效判断。
- 邮箱资格失败进入邮箱表单的持续错误，适配成单条面板，位置在邮箱控件之后、“继续”之前。
- 未申请时标题为“暂时无法注册”，文案为“未找到该邮箱的申请。”，说明为“请先申请加入，获批后再回来注册。”，Action 使用已有加入回调。
- 不符合资格、限流及临时失败使用准确的固定文案；只在存在实际可执行操作时提供 Action，不强制添加按钮。
- 入口参数错误和自动邀请链失败也必须落到当前表单的同一展示入口，不能因移除流程层 Alert 而消失。
- 验证码字段错误只在验证码字段显示；不再由流程层重复显示相同错误。重发失败和完善账号的非字段失败使用面板。
- 重新提交清除上次相关错误；新结果替换旧结果。修改邮箱清除旧资格错误；返回、关闭与卸载使旧请求结果失效。
- 内容变化时滚动回到列表起点，方便读取新结果；内容未变时的普通重渲染和冷却计时不重置滚动位置。
- 完成注册和主动重发的既有成功反馈保留；停止同一失败的重复 Alert 和 `ExMessage.error` 输出。

适配层不得绕过 `@workspace/api-client`；不改变现有 `alert: false` 请求行为。通用组件不承担错误码映射、请求重试策略或会话处理。

## 可访问性

错误更新使用单一的 polite live 区域，不把标题、整个面板和每条错误分别设为重复播报的 alert。列表使用语义化列表；装饰图标和序号不重复播报，数量与文案能够被读取。

发生邮箱资格问题时，邮箱控件关联对应面板；已有字段错误继续关联自己的 FieldError。错误移除时同时移除失效描述引用。使用键盘能够聚焦溢出列表并滚动到最后一条，Action 可独立聚焦；不因面板刷新抢走输入焦点。

## 验证与验收

共享组件的行为测试覆盖空列表、单条、多条、可选说明、可选标题、Action 有无及有效、非法高度配置。尤其断言无 Action 时不存在底部容器或分隔线，而不只是按钮不可见。

注册流程测试覆盖 page/modal 下的 404、409、限流及网络失败；每次只有一个持续反馈，不发送同内容错误通知；修改邮箱、重试、返回及卸载清除或拒绝旧错误。已有 StrictMode、自动邀请链、验证码重试、冷却与成功跳转测试继续保留，修改现有资格失败“通知一次”的预期为“持续反馈一次”。

真实浏览器单独验证 160、240、320 px 整体高度上限，标题与 Action 固定、最后一条可达、无 Action 后列表获得空间、长文本换行、明暗主题、窄屏和弹窗。jsdom 不验证实际布局与滚动高度。

设计预览已经验证空列表高度为 0、单条自然收缩、8 条在 160/240 px 面板内溢出滚动，以及键盘能够滚动到最后一条。该证据只支持预览，不代表共享组件或注册页面实现已通过验收。此前实际 `127.0.0.1:8080/register` 无法连接，实现后的真实业务页面仍须重新检查。

## 风险、兼容与交付

- 只删外围 Alert 会丢失入口或重发错误：实施时先建立所有分支的展示归属，再移除重复输出，并用分支测试检查。
- 高度限制可能让底部错误不可达：保持原生可滚动列表和键盘入口，以真实浏览器检查。
- 多条演示文案可能被误解为新增字段：演示是独立 UI 数据，不新增注册输入、密码规则或 API 字段。
- Action 不是必需项：不传时整个底部区域移除；说明和标题可以独立存在。

先实现独立组件与测试，再接入共享注册表单和流程，最后完成浏览器验收。只增加应用级 UI 导出，不引入运行服务或数据迁移；失败时可以回退组件及注册接线变更。自动检查、真实浏览器与部署验收分别报告，本阶段不部署上线。
