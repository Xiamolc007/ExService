## 1. 目标与已确认范围

实现一套独立的登录/注册组件，供站点 NavBar Modal 与独立页面复用。本地 Mock Server 按同一份 OpenAPI Contract 提供可验证的账号、注册与登录行为，未来 PHP 实现遵循相同 Contract。

已确认的产品决定：

| 项目 | 决定 |
| --- | --- |
| 登录信息 | 邮箱、密码 |
| 注册信息 | 邮箱、昵称、QQ 号、密码、确认密码，全部必填 |
| 唯一性 | 邮箱唯一、QQ 号唯一；昵称允许重名，不用于登录 |
| 密码 | 8–64 个字符，允许空格及各类字符，不强制字符组合，不自动 trim |
| 人机验证 | 本期不显示控件、不发送或要求验证凭证；保留后续接入位置 |
| 注册步骤 | 填写资料 → 发送邮件验证码 → 单独输入验证码 → 创建账号 → 成功提示 → 登录 |
| 邮件验证码 | 6 位数字，10 分钟有效；60 秒后可重发，旧码失效；连续输错 5 次后必须重新获取 |
| 验证码提交 | 输入满 6 位自动提交，支持粘贴 |
| 账号创建 | 邮件验证成功后才创建，创建时再次检查邮箱与 QQ 号唯一性 |
| 注册成功 | 不自动登录；保留邮箱，清空密码与验证状态，切换到登录 |
| 普通登录 | token 写入 localStorage，再整页刷新或跳转 |
| 普通 token | 签发后 7 天有效，不自动续期 |
| SSO 登录 | 不签发新的本站 token，不写入 localStorage；服务端确认关联请求成功后整页跳转成功页 |
| SSO 免登录 | 读取已有本站 token，服务端验证有效并确认本次 SSO 请求后跳转；无效或过期则要求登录 |
| SSO 发起方 | 后续由发起方轮询服务器获得结果，登录页面不负责轮询或传递 token |
| 模拟邮件 | 验证码只输出到 Mock Server 终端，页面不显示验证码 |

本期不实现真实邮件投递、人机验证供应商、生产 PHP/MySQL、SSO 发起方与轮询协议、外站回调、自动续期、找回密码、第三方账号登录、用户资料编辑。QQ 号只校验格式与唯一性，不验证归属。

## 3. 组件与应用职责

### 3.1 共享 UI：packages/components

- 认证表单负责登录、注册资料、邮件验证码、注册成功四个界面。
- 负责输入、字段校验、焦点、加载态、错误展示，以及登录/注册切换入口。
- 通过回调提交数据，通过 props 接收请求结果、错误与服务端时间信息；不访问 localStorage，不持有 API Client，不决定导航目标。
- Modal 容器负责开关、标题、描述、焦点约束与关闭后焦点恢复；内部直接复用认证表单。
- NavBar 的认证区域接收应用层的用户状态与操作回调，移除原有虚拟用户和占位登录状态。
- UI 可以声明表单草稿与展示状态类型，包含确认密码等 UI 专属信息；不得复制请求/响应 DTO。应用适配层使用生成的 Contract 类型组装请求。

### 3.2 应用层：apps/web

- 管理 API 调用、注册尝试标识、服务端结果到 UI 状态的转换。
- 管理普通登录会话恢复、token 保存/清除、退出登录与整页导航。
- 管理独立页面路由和 SSO 上下文；普通模式与 SSO 模式使用明确的流程分支。
- 独立页面容器复用认证表单；应用侧编排逻辑同时供 Modal 和独立页面使用。
- 密码、确认密码、输入的邮件验证码只保存在当前流程内存；不放入 URL、localStorage、sessionStorage 或日志。

### 3.3 视觉与可访问性

- 使用 ExUI 的 Dialog、Field、Input、InputOTP、Button 等公开组件，避免另外安装其内部实现库。
- CSS Modules 负责布局；颜色、边框、圆角使用已存在的 ExUI Token；间距与尺寸遵循根字体缩放。
- 沿用全站主题，保留 `main.tsx` 唯一的样式导入和主题 Provider。
- 表单单列排列，邮箱验证码界面只显示目标邮箱、验证码输入、重发与返回修改入口。
- Modal 在小屏可滚动，内容不超出视口；独立页面采用居中的表单区域。
- 所有输入有可访问标签，错误通过 aria 属性关联；状态变化可被辅助技术感知。切换步骤聚焦标题或首个输入。
- 验证码提交失败后允许编辑或明确重试；不得因仍有 6 位内容而循环自动请求。

## 4. 用户流程

### 4.1 注册

1. 用户填写第一步资料，客户端先检查必填、格式与两次密码一致。
2. 服务端校验并创建待验证注册，保存密码哈希，生成邮件验证码，返回注册尝试标识与有效期、下次可重发时间。
3. 页面进入验证码步骤。模拟投递仅在 Mock Server 终端打印收件邮箱和验证码，不打印密码、token 或完整请求。
4. 输入满 6 位或粘贴完整验证码后提交。服务端检查尝试状态、验证码有效期与错误次数。
5. 验证通过后，以事务创建账号并消费本次注册尝试；唯一约束处理最终竞争。未验证的资料不预占邮箱或 QQ 号。
6. 显示注册成功，短暂停留后自动切换登录，可通过“前往登录”立即继续。
7. 保留邮箱；清空密码、确认密码、验证码和旧错误。Modal 在原弹窗切换；独立注册页进入独立登录页；SSO 上下文继续保留。

邮件验证码重发由服务端限制，前端倒计时只是展示。重发后有效期重新计算为 10 分钟，错误次数归零，旧码立即无效；达到 5 次错误后，仍须满足 60 秒重发间隔。

返回修改时使旧尝试不可继续完成注册，保留非敏感资料，重新输入密码。新提交产生新的验证码；新建尝试不能绕过同一邮箱的发送冷却。关闭流程或刷新会清空浏览器内的注册进度，用户重新开始，服务端旧尝试仍受过期与冷却约束。

成功的注册尝试保留可判定的完成状态与短期重试所需的校验信息；客户端因丢失响应重试相同验证提交时，可以获得已完成结果，不重复创建账号、不重复扣减次数。重试仍须证明持有同一尝试及正确验证码，不能只凭邮箱查询完成结果。不同注册尝试竞争相同邮箱或 QQ 号时，返回相应字段冲突。

### 4.2 普通登录与登录态

服务端验证邮箱密码后签发随机的不透明 token。前端成功保存到 localStorage 后再执行导航：

| 入口 | 登录成功后的行为 |
| --- | --- |
| NavBar Modal | 整页刷新当前页面 |
| 普通独立登录页 | 整页跳转首页 |
| SSO 独立登录页 | 不保存新 token，整页跳转 SSO 成功页 |

页面启动时读取普通 token 并查询当前用户。验证完成前显示加载态，不将本地存在 token 直接视为已登录。有效时显示昵称与头像；明确无效、过期或已撤销时清除 token；网络或服务端暂时失败时保留 token 并允许重试。

localStorage 无法读取或写入时显示可恢复错误；普通登录不能在写入失败后假装已经持久化并跳转。退出登录成功后服务端会话失效，清除本地 token 并刷新；若会话已经失效，仍允许完成本地退出；暂时性网络错误允许重试。

会话从签发时起固定 7 天有效，使用不会延长期限。不增加刷新 token。token 不出现在 URL、日志或用户资料响应中。

### 4.3 SSO

- SSO 页面接收不透明的 `ssoRequestId`。它关联服务端已创建的待登录请求，不能由前端自行创建成功状态。
- 先验证 SSO 请求是否存在、未过期且允许当前操作；未知或过期请求显示错误。
- 存在本站 token 时，尝试由服务端验证会话并完成该请求。成功后直接进入成功页；明确无效时清除失效的本站 token 并展示登录表单。网络异常保留 token 并提供重试。
- 无有效 token 时，以邮箱密码登录并关联该请求。服务端记录结果，但不返回新的本站 token；前端也不覆盖或写入 localStorage。
- 注册与登录之间切换始终保留 `ssoRequestId`。注册成功不等于 SSO 成功，仍需随后完成登录。
- 同一 SSO 请求重复完成必须幂等，重复调用仍需通过密码或有效本站会话确认同一用户；已绑定的用户不能被另一个用户覆盖。浏览器显示成功前必须已收到服务端确认。
- 成功页提示用户返回发起应用；前端不轮询、不向外站传 token、不接受任意回跳 URL。
- 同一协议、域名、端口下的页面共享 localStorage；不同子域名不共享。本设计要求普通登录与 SSO 页面部署在同一 origin 才能复用本站 token。

本期只实现接收端所需的请求检查、密码确认与已有会话确认。开发验证使用显式 CLI 在固定本地 SQLite 中创建短期待登录请求，输出本地 SSO 登录链接；可通过显式 CLI 查看该请求结果。此能力不是新增 HTTP 路由，不在服务启动时自动执行，不接受任意数据库路径，也不定义未来生产轮询协议。

## 5. 服务端、Contract 与数据

### 5.1 需要设计的 operation 行为

以下是待新增能力，不代表现有 endpoint。具体路径、方法、operationId、请求与响应 schema 由后续 RFC 定义，并以修改后的 `api/openapi.yaml` 为唯一 HTTP Contract。

| 能力 | 行为 |
| --- | --- |
| 发起注册 | 校验资料与唯一性，创建待验证尝试，发送模拟邮件 |
| 重发验证码 | 校验尝试与冷却，更新验证码和时间 |
| 取消待验证注册 | 用于返回修改，令旧尝试失效；保留发送冷却约束 |
| 完成注册 | 校验验证码，以事务创建账号，支持完成结果重试 |
| 普通登录 | 校验凭据，返回本站 token 与过期时间 |
| 当前用户 | 校验本站 token，返回 UI 所需的用户资料 |
| 退出登录 | 撤销当前本站会话 |
| 检查 SSO 请求 | 检查当前请求是否可用，不公开用户敏感资料 |
| 以密码确认 SSO | 校验凭据，完成关联请求，不创建本站会话 |
| 以已有会话确认 SSO | 校验本站 token，完成关联请求 |

共用 `Authorization: Bearer` 传输本站 token，由应用层经共享 Client 添加。共享 Client 本身不读取浏览器存储。普通登录和 SSO 的返回结果不可混用，SSO 成功响应不包含本站 token。

所有错误沿用统一 envelope；字段映射使用稳定错误码，不通过解析错误文案实现。校验错误或固定安全文案以外的异常不向外回显。

注册响应不包含邮件验证码或密码哈希。本期人机验证不增加假 token、保留字段或模拟成功凭证；将来通过独立设计扩展表单接入点与 Contract 校验流程。

### 5.2 持久化责任

- 账号：规范化邮箱、昵称、QQ 号、加盐密码哈希及必要时间字段；邮箱、QQ 号分别唯一。
- 待验证注册：不透明标识、注册资料、密码哈希、验证码校验值、有效期、发送时间、错误次数、尝试状态、完成关联。过期、取消、完成后清理不再需要的敏感材料。
- 本站会话：账号关联、token 校验值、签发与过期时间、撤销状态；原始 token 仅在登录响应中交付。
- SSO 请求：标识、有效期、待登录/成功状态、绑定账号与完成时间；只承担本期接收端关联。

密码使用带独立盐的密码哈希算法，验证码使用带服务端密钥的校验值，token 使用不可逆校验值；具体算法、参数与本地密钥配置在 RFC 中定案。使用时间与随机源的可测试边界，不为了测试改生产有效期。

全部 Mock 数据只写固定本地 SQLite。新增 Drizzle migration，不修改 `0000_baseline.sql`，不提交数据库，服务启动不隐式迁移或创建 SSO 请求。

## 6. 异常与并发行为

- 字段错误在输入框附近显示，邮箱/QQ 号已占用映射到各自字段。
- 普通登录或 SSO 密码错误统一提示“邮箱或密码错误”。
- 验证码错误、过期、尝试次数耗尽、冷却中使用可区分的错误码与提示。
- 请求期间禁止重复提交；重发、验证、返回修改不能同时改变同一注册尝试。
- 网络错误保留当前表单内容并支持重试。关闭后重开的新流程不能被旧请求响应修改。
- 客户端取消请求不代表服务端停止；账号创建、验证码消费与 SSO 完成依赖服务端事务及幂等行为。
- 关闭或离开仍可发生服务端成功；客户端下次操作以服务端状态为准。已关闭表单的迟到响应不触发导航或 token 写入。
- 仅访问成功页 URL 不能完成 SSO。成功提示依赖当前浏览器流程中的服务端确认记录；没有该记录时提示从有效登录入口继续，不宣称认证成功。该记录只用于展示，不是授权凭据。

## 7. 集中审阅的建议默认值

以下补充项用于消除实施歧义，尚未逐项获得用户确认；完整文档批准时一并采用，可在审阅中调整。

| 项目 | 建议值 |
| --- | --- |
| 昵称 | 去除首尾空白后 1–32 个 Unicode 码点，允许中文、内部空格和 emoji，拒绝控制字符 |
| 邮箱 | 去除首尾空白，项目内按大小写不敏感处理，最大 254 字符；前后端采用一致的邮箱格式校验 |
| QQ 号 | 以字符串保存；去除首尾空白，5–12 位 ASCII 数字，首位非 0；这是本项目的接收规则 |
| 密码计数 | 按 Unicode 码点计数，不 trim、不做 Unicode 归一化；前后端规则一致 |
| 字段顺序 | 邮箱、昵称、QQ 号、密码、确认密码 |
| 登录/注册切换 | 同一容器中提供明确文字入口；切换保留邮箱、清除密码与旧错误 |
| 成功停留 | 注册成功提示停留 1.5 秒，另有立即前往登录按钮 |
| 关闭 Modal | 支持关闭按钮、Escape 与点击遮罩；清除表单内存，重开进入点击按钮对应模式 |
| 页面路径 | `/login`、`/register`；SSO 使用 `/login?ssoRequestId=...`，注册时保留参数；成功页 `/sso/success` |
| NavBar 行为 | 独立认证页内点击登录/注册切换当前页面，不叠加 Modal；SSO 页面保持 SSO 上下文 |
| 独立页面布局 | 沿用站点顶栏与主题，表单区域居中；不新增独立视觉主题 |
| token 存储键 | `exwebsite.auth.token`，仅存原始本站 token，不存密码与用户资料 |
| SSO 开发请求 | 显式 CLI 创建随机请求，10 分钟有效；仅服务本地验证，不是生产请求签发协议 |
| SSO 成功展示记录 | 应用在服务端确认后写入当前标签页 sessionStorage，记录请求标识及确认时间，5 分钟内仅用于成功页展示；不保存 token。写入失败时提示重试，不伪造成功 |
| 头像 | 无头像资料时使用昵称首个可见字符作为占位，不新增头像上传能力 |

昵称、QQ、邮箱的精确 Contract 表达式、错误码与边界样例必须在 RFC 和生成类型中保持一致。

## 8. 验收与实施约束

### 8.1 交互验收

1. NavBar 登录/注册分别打开对应模式，同一组件可在 Modal 和独立页完成注册。
2. 表单字段、唯一性冲突、密码一致性、验证码粘贴与自动提交符合约定。
3. 重发冷却、旧码失效、过期、5 次错误、返回修改、丢失响应后重试均有覆盖。
4. 未验证不创建账号；并发验证不重复创建；不同注册尝试竞争唯一字段时正确失败。
5. 注册成功回到登录并预填邮箱，不自动登录、不整页刷新。
6. 普通登录先写 localStorage，再按入口刷新当前页或跳转首页；恢复、过期、退出、网络异常、存储失败行为正确。
7. SSO 密码登录不写本站 token；已有有效 token 可免登录，但必须服务端完成请求后才跳转。
8. SSO 无效 token、未知请求、过期请求、重复完成、不同账号冲突、注册后继续登录均有覆盖。
9. 浅色/深色、桌面/窄屏、键盘操作、标签与错误关联可用；Modal 关闭后恢复焦点。

### 8.2 验证层次

- Contract 测试：真实 Fastify `inject()` 响应校验 + 注册 handler 原始返回值校验 + Contract/handler 双向覆盖。
- 数据行为测试：唯一约束、事务、过期、验证码消费、会话撤销、SSO 结果绑定与幂等；与开发数据库隔离，不重置用户数据。
- 前端行为测试：以用户操作和可见结果验证表单/容器/编排，不以源码字符串匹配代替交互。
- 真实浏览器验收：至少跑通 Modal 普通登录、独立页注册登录、SSO 密码登录与已有 token 免登录，核实整页导航和存储行为。
- 本地 SSO 验收通过显式开发命令创建请求、检查最终状态；不得将其报告成真实发起方轮询或生产 SSO 验收。
- 真实邮件、人机验证供应商、生产 PHP 和外部 SSO 系统均不属于本期已验证能力。

仓库当前没有 `TESTING.md`，实施时再次检查；若新增，以它为测试工作流唯一来源。执行顺序遵循 Contract-first：修改 Contract → `pnpm api:lint` → `pnpm api:generate` → handler/Client 调用 → `pnpm typecheck`、`pnpm test`、`pnpm build` → 浏览器验收。
