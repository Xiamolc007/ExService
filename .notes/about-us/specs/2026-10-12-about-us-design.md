# Exre About 页面设计

日期：2026-10-12。模块：`about-us`。状态：页面设计及通用内容层范围已获用户确认，进入本地实现与验证。

本设计将 `/aboutus` 建成 Exre 的整体介绍首页，通过社区、项目、团队、历程与 Media 子页展开长内容，通过成员 Modal 展开短介绍。内容在仓库中使用 MDX / YAML 维护，再构建发布。界面沿用 ExUI，内容编译使用 Fumadocs MDX，并按需使用 Core；保留现有 Vite、React Router 和 Fastify 架构。

## 1. 目标与范围

### 1.1 页面要回答的问题

读者进入首页后，能够认识 Exre 是什么、关心什么，以及社区、技术和创作怎样连接起来。继续浏览时，能够找到具体社区的故事、项目背景、参与的人、重要经历，以及我们使用过的音乐和影像。

内容面向第一次认识 Exre 的访客，也面向希望进一步了解作品与贡献者的社区成员。About 是持续维护的品牌内容入口，首页本身必须有完整介绍，不能仅是一组目录卡片。

### 1.2 本次设计范围

- `/aboutus` 默认介绍首页及五个栏目入口。
- 社区列表、Rifling-911 与 CAEP 介绍。
- 项目列表与项目故事详情。
- 团队与贡献者列表，以及成员简介 Modal。
- Exre 历程。
- Media 音乐与视频目录。
- 桌面、手机、浅色与深色布局，导航、阅读、占位素材与动效规则。
- MDX / YAML 内容组织与构建边界，以及未来插件文档和 Tebex 商店可以复用的部分。

本次不实现商店交易、插件文档站、CMS、站内搜索、内容上传、Outline 迁移或 SSR。未来功能仅保留明确的关联位置，不把这些功能当作已经发布。

### 1.3 已确认的选择

| 问题 | 已确认的结果 |
| --- | --- |
| 品牌方向 | B / 品牌叙事：大标题、充分留白、清晰段落，结合社区与创作素材。 |
| 默认首页 | `/aboutus` 介绍整体 Exre；并非个人 About，也并非纯目录页。 |
| 内容展开 | 长内容进入独立子页，成员短介绍使用 Modal。 |
| 栏目导航 | B / Apple 式轻栏目栏：左侧栏目标题，右侧轻量页面链接。 |
| 更新方式 | 编辑仓库中的 MDX / YAML，再构建发布。 |
| Fumadocs | 使用构建时内容能力；少量文档专用组件按源码适配方式复用。 |
| 运行框架 | 不引入 Next.js 后台，不替换现有 SPA、Fastify 或 ExUI。 |
| 素材 | 可以先使用明确的占位内容，用户后续补充真实素材与文案。 |

## 2. 信息架构与地址

| 地址 | 用途 | 内容来源（拟定） |
| --- | --- | --- |
| `/aboutus` | 默认介绍首页 | `apps/web/content/about/index.mdx` |
| `/aboutus/communities` | 社区介绍列表 | `apps/web/content/about/communities/index.mdx` 与社区元数据 |
| `/aboutus/communities/rifling-911` | Rifling-911 故事 | `apps/web/content/about/communities/rifling-911.mdx` |
| `/aboutus/communities/caep` | CAEP 历史社区故事 | `apps/web/content/about/communities/caep.mdx` |
| `/aboutus/projects` | 项目与创作列表 | `apps/web/content/about/projects/index.mdx` 与项目元数据 |
| `/aboutus/projects/:slug` | 项目故事详情 | `apps/web/content/about/projects/<slug>.mdx` |
| `/aboutus/team` | 团队与贡献者 | `apps/web/content/about/team.mdx` 与成员元数据 |
| `/aboutus/story` | 历程 | `apps/web/content/about/story.mdx` |
| `/aboutus/media` | 音乐与影像目录 | `apps/web/content/about/media/index.mdx` 与 `apps/web/content/about/media/items.yaml` |

成员正文位于 `apps/web/content/about/members/<slug>.mdx`，第一版不为每个人生成独立页面。项目或团队页可以打开同一个成员简介。成员 Modal 第一版不单独改变 URL；分享和深链接指向其所属页面，不承诺刷新后重开 Modal。

`/aboutus` 是规范首页地址。当前 `packages/components/src/SiteHeader.tsx` 使用 `/about`，实现时将其入口改为 `/aboutus`，并为 `/about` 添加到 `/aboutus` 的替换式跳转，避免旧链接落入 404。About 任意子页都保持全站 About 项的选中状态；这项改动只涉及导航目标与匹配规则。

About 社区故事与现有 `/communities/rifling-911`、`/communities/caep` 的申请/加入页面承担不同任务。仅在已确认运营状态和可用入口后显示加入链接，不复制申请流程。CAEP 以历史社区方式介绍，具体时间、事件与关联仍需真实资料，不从占位文案推断。

未知社区或项目 slug 使用现有 NotFound 行为。正常页内导航参与浏览器历史，可后退和前进。直接访问、刷新子页依赖现有 SPA fallback；内容接入不自动提供服务器端重定向或独立静态 HTML。

## 3. 导航与页面层级

### 3.1 全站导航

现有 `RootLayout` / `SiteHeader` 继续负责全站导航、品牌、账号、设置与通知，并保持其吸顶行为。视觉稿中的简化顶栏仅用于表达层级，正式实现必须使用真实组件，保留现有桌面与手机布局。

### 3.2 About 栏目栏

桌面栏目栏位于全站顶栏下方，与正文使用同一水平边界：

```text
关于 Exre                 概览  社区  项目  团队  历程  Media
```

左侧「关于 Exre」是返回 `/aboutus` 的链接，字号约为右侧链接的 1.5 倍。右侧为独立页面链接，取消 Tab 下划线、胶囊背景和滑动选中条。当前栏目通过较深文字和适度字重表达；深色主题使用较亮文字。栏目栏只有浅边界线，与全站导航形成不同层级。

栏目栏随内容滚动，不与全站顶栏同时吸顶。首页左侧保留「关于 Exre」，不再增加一条目录导航。子页将面包屑合入栏目栏左侧，如「关于 Exre / 社区 / Rifling-911」，最后一项不可点击；正文不重复面包屑，保留页面大标题。右侧仍提供栏目切换，面包屑与栏目链接使用各自命名的导航地标。

导航语义使用命名为「About 栏目」的 `nav` 和真实路由链接，不使用 `tablist`、`tab` 或 `tabpanel`。到栏目根页时，该链接使用 `aria-current="page"`；进入详情页时父栏目保持视觉选中，可使用 `aria-current="location"`，避免声称它就是当前详情地址。

### 3.3 手机栏目目录

栏目链接无法在一行保持舒适阅读时，折叠为：

```text
关于 Exre                              社区 ⌄
```

右侧按钮显示当前一级栏目：概览、社区、项目、团队、历程或 Media。社区与项目详情仍显示对应父栏目。展开后呈现六个入口，附一行简短说明，并明确当前栏目。

子页左侧同样显示面包屑；长标题在左侧可用空间内换行，栏目栏随内容增高，不挤压右侧目录按钮或隐藏导航目标。

目录使用 ExUI Popover 的公开组件与普通链接语义，不新增底层弹窗库。触发器可用键盘操作，带 `aria-expanded` 和与内容关联的可访问名称；展开后 Tab 能到达每条链接。Escape 或点击外部关闭，Escape 关闭后焦点回到触发器。选择页面后关闭目录，焦点转到新页面标题。

目录靠右对齐，宽度受视口约束，不产生横向滚动；触发器至少提供 44px 高的点击区域。最终折叠点按真实顶栏与中文文本的可用宽度验证，不能把视觉伴侣的固定 390px 模拟宽度当作唯一手机断点。

## 4. 页面内容与布局

### 4.1 首页 `/aboutus`

首页按照「我们是谁 → 为什么在一起 → 去了解具体故事」组织。

| 顺序 | 区块 | 内容与表现 |
| --- | --- | --- |
| 1 | 品牌首屏 | 占满视口，只显示居中的 Exre Icon、黑白 Shader 背光与底部「向下探索」提示。保留全站顶栏，About 栏目栏移到下一屏。 |
| 2 | Exre 简介 | 承接栏目栏，显示引导标识、大标题、概述、小标题和介绍正文。桌面标题与正文分栏，手机顺序阅读。 |
| 3 | 三个主要入口 | 社区、项目与创作、团队与贡献者。每项有不同类别的封面、简短说明与明确目的地。桌面三列，手机单列。 |
| 4 | 两个次要入口 | Media 与历程，采用轻量文字入口，不重复主卡片的大画幅。 |
| 5 | 页面收尾 | 简单品牌与相关入口，不增加重复目录或虚构数据。 |

2026-10-12 用户确认首屏只保留 Exre Icon，Hero 占满视口，并将初版全屏图标的宽高缩小 50%。图标始终保持原始比例；背景采用固定轮廓、移动背光的黑白 Shader，参考本地 `lightbox_ps_service` 的 Hero 实现。标题与介绍保留为可编辑草案，放在下一屏，不作为已经确定的品牌宣言。

首页 MDX 的 `hero.headline`、`hero.eyebrow`、`hero.summary` 现在用于下一屏的介绍，正文与入口说明仍由内容维护。首屏固定使用 Exre Icon，不显示文案、上传主图或浏览 CTA。「向下探索」使用真实内容锚点，可以点击并将焦点转到介绍标题；减少动态效果时即时滚动。区块顺序与响应式布局由页面模板负责，加入、购买等动作仍放在具体社区或项目的上下文里。

### 4.2 社区列表与详情

社区列表先简述 Exre 与社区的关系，再以两张不同状态的卡片呈现 Rifling-911 和 CAEP。卡片包含名字、定位、状态和介绍入口。状态不靠颜色独立表达。

Rifling-911 详情依次解释世界背景、体验理念、怎样共同创造故事，以及相关团队、项目与 Media。CAEP 详情以历史叙事组织：为什么开始、共同经历、留下什么。未来提供具体日期、图片或事件时添加到对应段落，不用虚构在线人数、规模、年份或成就填满版面。

正文保持阅读宽度；有素材时穿插影像与图注。加入/体验按钮只有在目标和社区状态明确后出现。历史社区不出现暗示仍在开放的加入按钮。

### 4.3 项目列表与详情

项目列表说明 Exre 做哪些类型的工具、插件和创作。每个条目显示名称、用途、当前状态与详情入口；项目数据不足时用明确的示例项目，不将其当作已发布商品。

详情正文按「为什么做 → 做了什么 → 谁参与 → 现在在哪里」展开。展示关键体验、截图或代码时，优先使用适合该内容的展示组件。相关成员可以打开 Modal；社区、Media、已存在的公开项目地址使用链接。

项目故事与未来商品详情分开。项目可以关联 `/store` 或插件文档，但第一版没有有效目标时隐藏对应动作，不显示空链接、虚构价格、库存或购买状态。

### 4.4 团队与成员 Modal

团队页包含介绍文字，以及团队成员和贡献者条目。条目从成员 MDX 元数据生成，展示姓名、头像或占位图、角色、简短贡献描述。可以按成员类别分组，但不预设未确认的组织层级。

成员卡片是打开简介的按钮。Modal 使用 ExUI `Modal`，包含必需标题、角色、简短经历、参与工作和有效公开链接。关闭按钮中文可访问名称为「关闭成员简介」。没有操作时不创建空 footer。

桌面采用约 32rem 的阅读宽度，内容长时内部滚动。手机沿用 ExUI 默认全屏行为，正文可滚动，标题与关闭按钮保持可访问。打开、Escape、外部关闭、焦点约束与归还交给公开组件；关闭后回到打开它的成员卡片。不同成员使用各自正文，不能复用同一段示例介绍冒充所有人。

跨页面复用成员引用，使用稳定 slug。引用的成员不存在时构建失败，不在运行时打开空白 Modal。浏览器验证还须覆盖长标题、长正文、短页与长页之间的导航，以及弹窗开关时顶栏横向位置。

### 4.5 历程

使用垂直时间线讲真实阶段与转折。每个节点有日期或明确的时间范围、标题、正文及可选关联作品/社区/Media。时间标注来自资料；未补充时标为占位，不能自动生成假日期。

时间线采用连续阅读，不加入拖动、横向时间轴或长时间锁定滚动。节点间距随正文长度自然扩展；手机保持单列。后续更详细的阶段内容可以进入同页章节，不在第一版新增一套事件详情路由。

### 4.6 Media

Media 是我们使用过的音乐和视频的内容目录。页首说明它们与社区或创作的关联，下方提供「全部 / 音乐 / 视频」筛选。筛选仅作用于本页条目，使用按钮及 `aria-pressed`，与栏目路由导航区分。

每个条目展示标题、类型、创作者、封面或占位图、来源与使用背景；可关联具体社区、项目或历程段落。试听/观看入口指向有效的原始来源，显示明确动作与来源平台。缺少 URL 时显示「来源待补充」，不创建假的播放按钮。

第一版采用封面、文字和外部来源入口，不新增内嵌播放器、平台 iframe 或 Media 详情路由。点击原始来源才进入对应平台。页面没有音乐或视频自动播放，也不把第三方媒体文件重新托管到 Website。

筛选无结果时显示一句清楚的空态，并提供回到「全部」的按钮。封面加载失败保留占位，创作者与来源仍可阅读。初始条目量少时不做搜索、分页或虚拟化；条目增长后另行评估。

## 5. 视觉与素材规范

### 5.1 整体表达

采用大标题、内容之间的留白、轻边界与少量有辨识度的主视觉。重点放在 Exre 的具体故事和作品，不用大量玻璃卡片、粒子效果或渐变装饰替代内容。

浅色以 ExUI 页面/内容表面与正文 token 为基础；深色继承同一主题体系。深色中的正文、弱化文字、分隔线、封面和 Modal 都需要独立验证对比度，不能只把背景变黑。主视觉的深色图形是品牌素材自身的设计，不是另一个页面主题。

字体使用现有 ExUI 字体体系与中文回退。视觉稿所用临时字体栈、十六进制颜色、外侧灰色工作台、模拟窗口边框、预览按钮和文件说明不进入产品界面。生产组件使用 CSS Modules 与现有 ExUI token，不新建页面专属 token 系统，也不重复导入全局样式。

About 栏目的页面标题、正文小标题、卡片标题与「关于 Exre」导航标题统一使用 `--exui-font-weight-bold`；正文段落保持常规字重。成员 Modal 的正文小标题沿用同一约定。

### 5.2 尺寸与阅读节奏

下列尺寸是按 CSS px 描述的设计目标，实现时使用 rem、流体尺寸与 ExUI 缩放约定。

| 元素 | 桌面目标 | 手机目标 |
| --- | --- | --- |
| 页面主体 | 最大约 1150px；外侧留白随视口增长 | 两侧约 24px；窄屏适当收缩 |
| 首页主标题 | 约 56–64px，行高 1.15–1.2 | 约 36–42px，避免中文孤字 |
| 子页主标题 | 约 44–56px | 约 32–36px |
| 主要正文 | 约 16px，行高 1.75–2 | 同样以 16px 为阅读基准 |
| 栏目标题 / 链接 | 约 20px / 12–14px | 约 18px / 12–14px |
| 阅读正文宽度 | 约 40–44rem | 随内容宽度 |
| 主要区块间距 | 约 56–88px | 约 32–48px |
| 栏目栏高度 | 约 56px | 约 54px |

正式页面正文不机械照搬缩小的视觉稿字体。手机首屏标题、段落、入口和目录必须保持可读与可点击；200% 缩放、320px 窄屏与较长中文文本不能导致横向滚动。

### 5.3 素材位置

| 位置 | 首版无资源时 | 后续替换 |
| --- | --- | --- |
| 首页首屏 | 自有 Exre 标志与克制的品牌图形 | 自有品牌影像或更完善图形，保留文字阅读顺序 |
| 社区入口 | 明确标识的社区图片占位 | 社区内真实截图或摄影，优先横向画幅 |
| 项目入口 | 界面示意或中性占位 | 项目截图、作品图或插件演示封面 |
| 团队入口 | 中性人物占位图形 | 团队活动或成员素材 |
| 成员头像 | 中性头像 / 首字母占位 | 本人确认的头像，预留方形或竖向裁切 |
| Media 封面 | 音乐 / 视频类别占位 | 对应来源封面或自有配图 |

图片由记录中的资源路径、替代文字、可选图注和裁切位置配置。替换图片不会要求改组件结构。资源必须有确定宽高或比例，避免加载后推移正文；首屏必要素材优先加载，其余按需加载。大图提供适当尺寸，手机不下载无必要的完整原图。

无图片时提供完整 fallback，而不是损坏图片图标或空白卡片。纯装饰图形不重复朗读标题；有内容意义的图片提供替代文字。占位文本和图像不伪装成真实事实，发布内容前核对真实名称、日期、状态与公开入口。

## 6. 动效与交互规范

动效用于解释出现、反馈和关闭，不阻挡阅读。以下数值是实现目标，需在真实页面上验证。

| 场景 | 动效目标 | 约束 |
| --- | --- | --- |
| 品牌首屏 | 固定 Exre 轮廓，缓慢移动背光；桌面鼠标只改变光源 | 30fps，减少动态效果时保持静帧；离屏和后台暂停；WebGL 失败显示静态 Icon。 |
| 卡片悬停 / 焦点 | 120–160ms 的边框或表面反馈 | 键盘有等价反馈；不放大整张卡片。 |
| 栏目链接 | 约 150ms 的颜色反馈 | 无移动选中条，不伪装成 Tab。 |
| 手机目录 | 140–180ms 的淡入及最多 4–6px 位移 | 关闭可立即响应，不延迟导航。 |
| 成员 Modal | 沿用 ExUI 的打开与关闭动效 | 不再叠加另一套弹窗动画。 |
| Media 筛选 | 即时改变结果与选中状态 | 不用退场动画阻塞键盘焦点或隐藏空态。 |

本次只增加用户确认的品牌背光与向下滚动提示，不做滚动接管、视差视频、长篇 sticky 动画或自动播放。正文不需要等待 IntersectionObserver 才能阅读。Shader 及轮廓计算按需加载，不新增重型动画库。

`prefers-reduced-motion` 下移除位移与非必要过渡，保留即时状态反馈；禁用动效时页面与目录、Modal 仍能正常使用。页面切换不增加全屏过场；普通前进进入 About 首页时回到首屏并聚焦可见的滚动提示，子页聚焦标题。浏览器后退恢复尽可能接近此前的阅读位置。

## 7. MDX / YAML 内容设计

### 7.1 内容目录

以下为拟定目录，当前尚未创建生产内容：

```text
apps/web/content/about/
  index.mdx
  communities/
    index.mdx
    rifling-911.mdx
    caep.mdx
  projects/
    index.mdx
    <slug>.mdx
  team.mdx
  members/
    <slug>.mdx
  story.mdx
  media/
    index.mdx
    items.yaml
  assets/
    <owned-image-files>
```

MDX 承载文章与简介，frontmatter 承载列表需要的结构化信息。社区、项目和成员卡片从对应文件元数据生成，避免在另一份 YAML 中再次维护同一姓名、标题或描述。首页入口的说明可以直接在首页 MDX 中编辑，但目标必须经过内容映射校验。

Media 使用 YAML，因为音乐/视频条目以标题、作者、来源和关联信息为主。历程第一版保留在 `story.mdx`，以受支持的时间线组件组织内容，不额外创建一份重复的事件数据库。

### 7.2 内容字段

| 内容 | 必需信息 | 可选信息 |
| --- | --- | --- |
| 普通页面 | 标题、描述、正文 | 首屏标题、引导标识、主图与图注 |
| 社区 | 稳定 slug、名字、简介、排序、真实状态或明确占位状态 | 封面、确认后的加入入口、关联项目/成员/Media |
| 项目 | 稳定 slug、名字、用途、排序、真实状态或明确占位状态 | 封面、公开地址、关联成员/社区、已存在的文档/商店目标 |
| 成员 | 稳定 slug、姓名、角色、简短贡献、类别与排序、简介正文 | 头像、参与项目/社区、公开个人链接 |
| Media | 稳定 id、类型、标题、创作者、使用背景 | 来源 URL、封面、关联社区/项目/历程 |

作者可以将条目标为草稿；草稿不进入正式列表或公开内容分块。没有来源的 Media 可以保留明确的「来源待补充」状态。可选的日期、运营状态和外链只由真实资料补充，不由编译器生成。

示例结构仅说明编辑方式，内容明确标注为占位：

```mdx
---
title: 成员姓名占位
slug: example-contributor
role: 具体职责待补充
summary: 具体贡献待补充
kind: contributor
order: 10
draft: true
---

这里补充成员的简短经历。

## 参与的工作

这里介绍具体项目与贡献。
```

```yaml
items:
  - id: example-music
    type: music
    title: 歌曲名称占位
    creator: 创作者待补充
    usage: 使用场景与选择理由待补充
    draft: true
```

完整字段类型、默认值和集合配置在书面设计获确认后的 RFC 中定义；实施不能把示例中的占位姓名和内容当成真实资料。

### 7.3 作者组件与校验

提供小范围、稳定的 MDX 组件映射：标准段落、标题、列表、链接、图片与图注，以及首页入口、关联链接、时间线和必要的提示/代码展示。内容作者修改文案、图像和元数据时不需要了解 Fumadocs 布局。MDX 来自可信仓库，是构建输入；第一版不接受用户上传或运行时远程 MDX。

构建校验必填字段、slug/id 唯一性、排序、媒体类型、资源路径与关联目标。缺失成员、项目或社区引用、无效 URL 或缺失资源给出文件和字段位置，并使构建失败。没有可选资源时走 fallback，不与「指定了却不存在」混为一谈。指向草稿的公开关联必须删除或改为可用目标，不能发布死链。

外部来源仅允许明确支持的 HTTPS 地址；应用不执行 YAML 中的脚本或任意 iframe。页面路径从内容注册表解析，不从用户输入拼接模块路径。修改 `.mdx` 或 `.yaml` 在开发时热更新，生产重新构建；浏览器加载编译后的页面与必要元数据，不下载原始内容配置或完整全集正文。

## 8. 技术接入与未来复用

### 8.1 当前框架匹配

当前 `apps/web/src/main.tsx` / `apps/web/src/App.tsx` 为单一 BrowserRouter 的声明式 SPA，`RootLayout` 负责共用顶栏。About 加入这一布局和路由树。`apps/web/package.json` 的 React、Router、Vite 与 ExUI 继续使用项目依赖，不启动第二个 Web 应用。

构建链为：仓库内容 → Fumadocs MDX 编译和 schema 校验 → 页面/元数据映射 → 路由按需加载 → ExUI 样式下的内容渲染。使用 Fumadocs Core 的具体功能以需求为限，不为了包名安装没有消费者的能力。

静态 About 不新增 Fastify endpoint、OpenAPI operation、数据库表、后台进程或运行秘密。正式 Server 与 Contract-first 工作流继续保持原边界。构建不访问数据库、Outline 或在线内容服务。

### 8.2 Fumadocs 采用方式

采用 Fumadocs MDX 的常规集合配置和 Vite 接入。已验证候选关闭 Macro，并关闭插件对现有 Vite 配置的自动更新；隔离实验与限制见 `.notes/about-us/reviews/2026-10-11-fumadocs-integration-audit.md`。当前实验版本是 MDX 15.4.7、Core 16.17.1，不代表未来实施可以跳过版本和依赖核验。

不复制 Next.js 文档站模板，不添加 Fumadocs 默认 RootProvider，不引入另一套主题偏好或全局 Tailwind/preset。ExUI 全局样式仍只在 `apps/web/src/main.tsx` 导入一次；其文档主题桥接入口不能在当前应用中未经审查直接叠加导入。

`fumadocs-ui` 的复用限定为确有需求的文档专用组件源码适配：优先考虑 CodeBlock，后续需要时再引入 Steps、Files 或类型表。适配版用 ExUI 的按钮、Tab 等公开组件和 CSS Modules；移除 Next 专用逻辑、重复主题与底层 UI 依赖。保留上游来源和许可证，明确这是本地维护的适配版本，升级时逐项比对。

About 第一版不需要一次实现完整文档组件目录。出现真实代码段时至少支持构建时语法高亮、语言标识、横向滚动、复制与失败反馈。代码内容不在浏览器再运行高亮编译器；复制成功/失败经既有 ExMessage 通知，并遵守 `.ai/rules/frontend-notifications.md`。

### 8.3 影响与限制

| 边界 | 影响与验收要求 |
| --- | --- |
| Web 路由 | 新增 About 路由、旧入口跳转与前缀选中；保留声明式 Router。 |
| 构建 | 增加 MDX 配置、集合校验与内容分块；检查代理、HMR、生成目录和 React 单实例。 |
| UI | 新增局部模板与文档适配组件；保留 ExUI token、主题和全局样式唯一入口。 |
| 初始加载 | About 正文按路由分块；成员正文按需加载；不在首页打包全部未来内容。 |
| 服务端与数据 | About 静态内容不改 Contract、Fastify、数据库或 Outline。 |
| SEO | 页面可更新浏览器标题和描述；MDX 接入不自动带来 SSR、每页 HTML 或可抓取的分享卡片。 |
| 验证证据 | 隔离实验通过不等于当前仓库集成通过；最终检查必须在真实应用执行。 |

### 8.4 将来如何复用

用户确认本轮同时建设 Website 通用内容能力。`apps/web/build/content/` 负责与业务无关的文件解析、静态 MDX 检查、公开资源处理、注册表生成及开发更新；`apps/web/src/content/` 负责正文模块缓存、加载状态和可组合的 MDX 渲染接口。集合通过配置提供目录、schema、作者组件与引用校验，通用层不认识 About 路由、社区状态、成员或交易字段。

About schema、集合投影、关联和页面布局位于各自的 About 适配模块。代码块、图片、表格和 Callout 的无路由基础组件放入 `packages/components/src/content/`；链接导航和业务组件由 Web 集合注入。不新增 workspace 内容包。本轮提供基础渲染和集合机制；文档侧栏、搜索、版本切换仍由后续真实需求设计。

通用性必须由第二个非 About 测试集合验证：不同字段和目录能够复用同一解析、校验、构建与懒加载机制，不要求复制 About 核心实现。只有公开内容生成正文 import，草稿及其独占资源不得进入浏览器产物。

未来插件文档可复用内容编译、集合校验、链接解析、代码高亮和 ExUI 文档组件；目录、目录树、阅读侧栏和搜索根据文档需求另行设计。候选路径为 `/plugins/:slug/docs`，当前不注册。现有 `/docs/` 保留 Outline 归属。

未来 Tebex 商店可以复用内容编辑能力、项目叙事、媒体与内容关联。商品、价格、购物车、结账和交付以该业务正式方案为准，不进入 About 的 YAML 数据。About 项目页可关联商品与文档，不充当交易来源。商店和插件文档都不是本次设计获确认后可以直接实施的扩展范围。

## 9. 可访问性与失败状态

- 每页有一个正文 `h1`，MDX 标题从下一层级开始；视觉稿的 `h2` 不直接照搬到页面语义。
- 全站、栏目和面包屑使用不同的导航名称，避免无法区分的导航地标。
- 页面链接、打开 Modal 的按钮和 Media 筛选按钮各自使用相应语义，整张卡片不嵌套可点击控件。
- 键盘可以打开目录、进入子页、打开并关闭成员 Modal；保留可见焦点与恰当的焦点归还。
- 页面加载时保留必要布局和简短状态；内容模块加载失败时提供重试或返回上一级，不能只留下空白。
- 图片失效、无 Media 条目、筛选无结果、无项目内容与未知 slug 都有明确表现。
- 图片尺寸、目录弹层、Modal 滚动锁定和页面长短变化不会导致顶栏跳位或可操作内容被遮挡。
- 颜色与字重之外，当前链接有语义状态；正文与控件需通过实际对比度检查。
