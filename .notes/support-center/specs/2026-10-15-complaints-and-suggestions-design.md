## 1. 入口和界面

首页保留「功能和需求」「投诉和建议」两个入口。「投诉和建议」打开 ExUI Modal，先展示两张类型卡片：

| 类型 | 图标 | 说明 |
| --- | --- | --- |
| 反馈和建议 | `apps/web/public/3d-icons/Message.png` | 分享你的体验，提出对服务或社区的建议。 |
| 投诉 | `apps/web/public/3d-icons/Danger.png` | 说明你遇到的不当行为或不满意的体验。 |

复用现有类型卡片的 64px 图标、加粗标题、不透明背景及背景色 Hover。桌面两列，窄屏单列。选项读取期间显示骨架。两类表单提供「返回选择类型」，使用现有 Modal 尺寸、内容滚动、固定底部操作和键盘焦点恢复规则。

类型选择页与表单页均不提供底部关闭按钮。右上角保留关闭入口；有未提交内容时确认放弃，提交过程中关闭时保留恢复能力。

## 2. 表单和输入规则

| 输入 | 两类共同规则 |
| --- | --- |
| 标题 | 必填；沿用现有 trim、200 个 Unicode 码点和控制字符规则。 |
| 内容 | 必填；普通多行文本，使用主要内容输入框的较高尺寸，沿用 64 KiB UTF-8 原文与 Markdown 限制。 |
| 附件 | 选填；沿用 `FileUploader`，0–5 个，每个 1 字节至 20 MiB，总计不超过 100 MiB。 |
| 大文件补充信息 | 默认收起、选填；支持链接、提取码与说明，最多 16 KiB UTF-8。 |

字段使用现有 RHF/Zod 和 ExUI 控件，提供对应类型的 placeholder，明确标注选填项。`Type` 和 `Summary` 不增加为输入项。

## 3. 投诉匿名规则

仅「投诉」在底部提交按钮左侧提供「匿名」Switch，默认关闭。「反馈和建议」没有匿名开关，也不能通过 API 请求匿名提交。

实名提交沿用昵称与账号 UUID 写入 ClickUp「用户」字段的行为。匿名投诉完全省略该字段，也不自动在标题、正文或其他对外载荷中附加昵称或账号 UUID。服务端生成对外载荷，客户端不能传入任意身份字段。

两类均要求登录。本站保留提交者账号关联，用于权限、限流及恢复；界面解释为「匿名提交不会向 ClickUp 提供你的昵称和账号 ID；本站仍保留账号关联」。匿名仅隐藏系统附加的账号信息，用户填写的内容和附件保持原样。

匿名开关属于投诉草稿，切换类型时与投诉内容一起保留，不进入反馈和建议草稿。真正放弃草稿后恢复默认关闭。提交开始后，类型、内容、匿名设置和目标载荷一并固定；重试和恢复不能改变匿名规则。

## 6. 草稿、恢复和兼容

「功能和需求」与「投诉和建议」各自保留一份进行中的提交，使用独立的浏览器恢复标识；一份未完成的需求不能阻止投诉。入口内部仍一次处理一份提交。草稿正文与 File 留在当前页面内存，浏览器存储只保存恢复标识。

两类新表单接入既有接收、创建、上传、失败、结果待核对和完成流程。未知外部结果进入核对状态，不能盲目重新创建任务；匿名投诉同样具备关闭、重新打开和缺失附件重选能力。注销和账号切换停止后续推进，并保持归属校验。

Contract-first 增加表单类型和匿名规则；生成 Client 与运行时校验保持一致。数据库采用显式增量变更支持新表单及隐私快照校验，不删除已有六类 v2 反馈或暂存附件。已有冻结记录继续使用原目标与规则恢复，不重新解释为新表单。具体 schema、版本、接口分组和记录核对方式在实现 RFC 中确定。
