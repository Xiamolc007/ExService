## 目标与本期范围

为已登录的 Website 用户提供统一支持页：查看支持入口、快速排查常见错误、联系具体成员，并直接查看 ClickUp 开发进度。

本期包括支持首页、常见错误列表、常见错误详情、登录访问控制和官方 ClickUp 视图嵌入。功能建议、Bug 反馈与投诉只展示入口卡片，标注“即将开放”，不打开表单、不提交数据。开发进度不接入 ClickUp API，不在本站复刻 ClickUp 内部任务界面。

用户最初提出独立开发页，随后明确调整为：ClickUp 面板直接展示在支持首页，顺序放到最下面。本期因此不新增独立开发页。

## 页面与路由

| 路由 | 用途 |
| --- | --- |
| `/support` | 支持首页。 |
| `/support/errors` | 全部已发布常见错误列表。 |
| `/support/errors/:slug` | 单个错误的完整说明。 |

三个页面均使用 Website 现有站点布局、主题与认证状态。顶栏新增 **Support** 项，桌面导航与移动导航仅在 `authenticated` 时显示；支持子路由归属于同一导航项。导航组件接收展示状态，不自行读取 token 或调用 API。

未知错误 slug 或不支持的子路由显示站内 404，并提供返回常见错误列表或支持首页的入口。登录访问检查先于支持内容的挂载，不能因未知地址绕过访问限制。

## 登录与访问

复用 `AuthProvider` 的真实会话核验结果，不以 `localStorage` 中存在 token 作为登录依据。

| 会话状态 | 页面行为 |
| --- | --- |
| `loading` | 只显示登录状态检查提示，不挂载支持内容或 ClickUp iframe。 |
| `anonymous` | 不显示支持内容。在原地址显示“登录后可访问支持中心”和登录按钮；按钮打开已有登录弹窗。 |
| `unavailable` | 不显示支持内容。展示固定错误说明与“重试登录状态”入口，不把网络错误当作已退出登录。 |
| `authenticated` | 加载并展示当前支持路由。 |

直接访问深链接时保留当前站内地址。现有弹窗登录成功后会重新加载当前页面，因此可恢复到原支持地址，不新增任意 `returnTo` 跳转。关闭登录弹窗后仍保留登录提示页；不通过反复自动打开弹窗阻止用户关闭。

退出登录、其他标签页的会话同步或认证状态变化时，卸载支持内容和 iframe；重新核验成功后才恢复展示。会话处理继续归现有认证模块。

本期登录限制针对本站页面入口与展示。仓库编译的静态内容不能作为秘密存储；普通 ClickUp 公开分享链接的访问权限也不由 Website 会话接管。

## 支持首页

首页顺序固定为：介绍、反馈入口、常见错误与联系人、ClickUp 开发进度。

### 介绍与视觉

桌面端沿用 About 页的左右布局：左侧为小标题“支持中心”及两行粗体主标题“遇到问题，一起解决。”，右侧为简短的支持说明。页面内容宽度、文字层级、留白、圆角和边框沿用 Website/ExUI 既有规范，不引入新 token 层或独立主题。

反馈卡片使用浅灰背景与普通文字，不放彩色插画。页面保留一个 h1，后续区块使用 h2，卡片与案例标题使用合适的下级标题。正式页面不包含预览工具栏、示例标签或实现说明。

窄屏依次堆叠介绍、三张反馈卡片、常见错误、联系人和开发面板。长姓名、邮箱和案例标题可换行，不能撑出页面横向滚动。主题由应用现有 Provider 控制；明暗主题均使用 ExUI 颜色，不在页面强制另一套配色。

### 反馈与建议

三张卡片分别为 **功能建议**、**Bug 反馈**和**投诉**，包含用途说明及“即将开放”状态。未开放卡片不作为链接或可提交按钮，不产生点击成功提示，也不展示无法提交的输入框。

### 找到解决办法

区块内展示最多三个由内容作者精选的已发布案例。这里的“常见”是编辑选择，不伪造访问量、反馈次数或热度排名。

每条案例具有标题、简短排查说明和完整详情入口。默认折叠；点击标题、Enter 或空格可展开说明，显示明确的展开状态。允许分别展开多条，点击同一标题可收起。展开不改变 URL、不跳到详情页；“查看完整说明”才进入该案例的独立路由。

区块底部的 **查看更多常见错误** 进入 `/support/errors`。少于三条精选时按实际数量展示，不补假案例；没有精选但存在其他内容时显示说明与查看更多入口；整个知识库为空时显示“常见错误内容整理中”。

### 联系成员

成员卡片展示头像、姓名和职责，可选展示 QQ 与邮箱。头像缺失时使用成员首字或通用头像回退；不使用无关人物照片代替真实成员。

QQ 提供复制操作，复制结果通过现有 `ExMessage` 提示；复制失败时保留可选择的文字。邮箱使用经过校验的 `mailto:` 链接。未提供的联系方式不显示虚构值或无效按钮，不承诺未确认的工作时间、响应时限或处理结果。

没有成员资料时，正式页面显示“联系人资料整理中”，不把预览中的“成员姓名待补充”当作真实卡片发布。

## 常见错误内容

常见错误使用独立的 `support` 内容集合，复用现有通用内容编译、静态语法与引用校验、资源处理和正文加载机制，不复制 About 编译器。

内容源建议集中在 `apps/web/content/support/`：错误正文位于 `errors/`，成员元数据位于 `contacts.yaml`，嵌入及栏目设置位于 `settings.yaml`，图片位于集合的 `assets/`。字段 schema 与公开投影属于 Support 业务适配器。

错误条目拥有稳定 slug、标题、列表摘要、分类、快速排查说明、草稿标记及可选精选顺序。快速说明是独立的纯文本元数据，正文是 MDX；不从正文随意截取 HTML 充当摘要。精选顺序必须唯一，草稿不能进入列表、首页案例或发布后的正文加载器。

列表按显式编辑顺序展示所有已发布条目，显示标题、摘要和分类。点击整行进入对应详情。本期不增加搜索、统计热度、投票、分页或高级过滤。

详情页提供面包屑、标题、摘要、分类与正文。正文按内容需要组织为“问题表现”“可能的原因”“排查步骤”“仍未解决”等部分；桌面端可生成正文目录，窄屏优先保证正文阅读。详情页提供返回列表和前往首页联系成员的入口。

作者沿用通用内容系统支持的 Markdown 与白名单组件，不通过 MDX 执行任意脚本。正文中的链接与资源须校验，不允许公开条目引用草稿或不存在的错误条目。分类与路由归 Support 适配器，不进入通用共享 UI。

预览中的三个案例仅用于说明交互，不作为已批准运营内容自动发布。真实条目须由作者核对问题、适用范围和解决步骤后录入。

## ClickUp 接入

采用 ClickUp 官方生成的、用于向外部网站展示开发进度的视图嵌入代码。嵌入区域在 `/support` 最下面，不影响前面的支持入口、案例和联系人。旁边保留 **在 ClickUp 中打开** 的原始分享链接。

接入时读取并核对用户提供的代码。本期以单 iframe 视图为范围：保留官方 iframe 的 URL 与必要参数，在应用组件中受控生成 iframe，不将整个 HTML 字符串交给 `dangerouslySetInnerHTML`。来源 URL 必须为 HTTPS，使用由该份代码核实后登记的固定 ClickUp 域名清单；不接受任意来源或脚本。若实际官方代码还要求额外脚本或不同视图类型，须先核对其用途与本期范围，不静默扩大接入。

iframe 具有可访问标题、响应式外层宽度和足够阅读任务的高度。可以调整本站外层留白和尺寸，不尝试改写跨域 ClickUp 内部界面。登录确认前不挂载 iframe；离开页面或退出登录时卸载。下方视图可使用浏览器的懒加载减少首屏请求。

没有配置时显示“开发面板暂未配置”，不生成空 iframe或虚构进度。原始分享链接未配置时不展示打开按钮。实际连接失败、分享被撤销或浏览器阻止第三方 Cookie 时，保留外部打开入口与简短说明；跨域限制下不能仅凭 iframe `load` 事件宣称任务已成功显示。

普通公开分享对持链接者可见，Website 登录只控制本站入口。ClickUp Dashboard 与 Board 任务视图不同；官方文档不支持将 Dashboard 向 Workspace 外公开分享。需要接入的必须是实际允许分享与嵌入的视图。Enterprise 的 OIDC 公开视图认证不属于本期。

能力与来源详见 `.notes/support-center/specs/2026-10-12-clickup-integration-research.md`；官方依据为 [公开分享和嵌入说明](https://help.clickup.com/hc/en-us/articles/6309298874775-Share-locations-and-items-with-a-public-link)及 [Dashboard 分享范围](https://help.clickup.com/hc/en-us/articles/6312198211863-Share-Dashboards)。

第一期业务 UI 默认放在 Support 页面目录，不因单次使用提前扩展 `packages/components/`。只有已有通用组件继续复用；共享组件不访问 API或携带 Support 路由表。

第一期不修改 HTTP Contract、不增加数据库表或迁移，不修改 Outline 或 `/docs/` 的实现。现有 `/auth/me` 会话核验仍通过共享 API Client。若后续反馈提交或受控数据读取需要新 API，另行遵守 Contract-first 流程。

## 错误与恢复

- 认证不可用时提供重试，不显示支持正文或第三方视图。
- 正文加载中提供状态提示；失败时提供重试和重新加载当前页面，沿用既有模块加载恢复边界。
- 修改条目、返回列表或页面卸载后，旧加载结果不能覆盖新页面；复用现有 `useContent` 的结果隔离。
- 图片失败保留回退布局；未知 slug 显示 404；空内容显示真实空态。
- ClickUp 内部故障不会阻止使用首页其他区块，不回显浏览器或第三方内部异常。

## 验收

实施后执行与变更相匹配的自动检查，包含 `pnpm --filter @workspace/web content:check`、`pnpm typecheck`、`pnpm test` 与 `pnpm build`。当前仓库没有 `TESTING.md`，具体测试编排沿用项目现有流程，并在实施前再次核对。

自动验证至少覆盖：四种认证状态、未登录深链接、登录/退出后的内容挂载；桌面与移动导航的入口条件；精选排序、数量、草稿和引用校验；案例展开、完整详情与查看更多入口；未知 slug、空态、正文加载失败和重试；嵌入配置的 URL 校验与登录前不挂载 iframe。

真实浏览器验收覆盖桌面/手机宽度、明暗主题、长文字、键盘展开与焦点、直接刷新详情路由，以及登录后返回原地址。真实 ClickUp 验收必须使用用户提供的代码与分享链接，检查视图显示、任务点击、窄屏尺寸、分享权限和第三方 Cookie 限制下的回退入口。

自动检查、浏览器交互和真实 ClickUp 接入分别报告。当前设计预览的页面切换与展开验证不等于上述正式功能验收；本期不执行部署上线。
