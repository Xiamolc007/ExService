# 团队页人物展示与开发团队招募设计

状态：已确认。用户在确认最终人物与招募预览后，补充要求上下两块各具有一屏最低高度，并支持 `/aboutus/team#join` 直接定位。本稿按这些明确要求更新，作为 RFC 的设计依据；尚未实施生产页面。

模块目录：`.notes/about-team/`。设计、RFC 与后续计划分别归入该目录的 `specs/`、`rfcs/`、`plans/`。

## 目标与确认范围

修改 `/aboutus/team`，参考用户提供的人物展示图，使用已选 A 的结构：居中标题、悬浮头像选择条、姓名、中央人物图片与两侧资料。成员信息来自 `apps/web/public/config.json` 的顶层 `teams` 数组，初始提供四份明确标注为占位的资料。

已确认的视觉要求：

- 不同成员拥有各自的颜色主题，初始四位分别使用蓝色、青绿、紫色、暖橙。
- 成员切换使用现有 `framer-motion`，同步过渡背景与强调色，并让人物、姓名和资料淡出／淡入。
- 主面板使用 `@paper-design/shaders-react` 的 `DotGrid`，保留用户给出的点阵参数，仅修改颜色配置。
- 浮动头像选择条使用 ExUI 的 `ex-glass` 材质。
- 左侧资料顺序为职责、简介；右侧展示擅长的事。
- 删除寄语区，不显示 `1 / 4` 一类计数。
- 在成员展示下方增加开发团队招募区块。用户授权自主展开文案与设计。
- 上下两块分别作为独立全屏章节，内容足够时每块至少 100svh，内容过多时自然增长；招募章节提供公开锚点 `/aboutus/team#join`。

本次仅涉及 Web 的展示、公开配置与内容。HTTP Contract、Server、数据库、Outline、依赖版本和部署不属于范围；提交与发布未获授权。

## 当前依据

`apps/web/src/pages/AboutUs/AboutUs.tsx` 当前组合栏目头部、MDX 正文、成员卡片和简介 Modal。`apps/web/build/about/definition.ts` 从成员 MDX 建立注册表及跨内容引用；项目与 Media 也使用这些引用。

`apps/web/public/config.json` 目前维护 QQ 与 KOOK 社区链接；`apps/web/src/join/community.ts` 已提供经过 HTTPS 检查的 `communityLinks`。`/join/rifling-911` 是玩家申请流程，不作为贡献者报名目标。

`framer-motion`、`@paper-design/shaders-react` 和支持 `ex-glass` 的 ExUI 已安装，无需新增实现库。全局 ExUI 样式继续由 `apps/web/src/main.tsx` 导入一次。

## 页面与内容层级

保留全站顶栏和团队子页已有的 About 面包屑、栏目导航。团队页使用独立布局，避免修改其他 About 子页的通用排版。

标题暂采用预览文案“不同的视角，同一个 Exre.”，引言为“认识社区、技术与创作背后的人。”。页面文案继续由 `apps/web/content/about/team.mdx` 维护；页面标题用于文档标题和面包屑。增加团队页专用的可选标题文案字段以区分栏目名称与展示标题，不改其他栏目字段语义。现有介绍正文和明确说明资料仍为占位的内容保留在标题区域，不因改版丢失。

主面板姓名使用二级标题。桌面为左资料、中央人物、右能力三列；人物图底边贴合面板下缘。头像用于选择，中央图用于人物展示，两者分别配置；图片缺省或失败时显示普通占位，不生成虚构人物或绘制替代插画。

选择条只有头像与选中状态，没有人数或当前位置计数。默认选中数组第一项。选择不改变 URL，不新增个人路由，不自动轮播。团队页直接展示配置中的完整短资料，头像不再打开简介 Modal；其他页面原有 MDX 成员引用与 Modal 保持可用。

成员数量由配置决定，不限制只能有四位。头像多时选择条在有限宽度内横向滚动，键盘焦点进入时使当前按钮可见。手机端按姓名、人物图、左侧资料、能力的顺序单列显示，简介不会固定高度裁切。

## 两屏高度与招募锚点

成员章节包含大标题、介绍正文和人物舞台；招募章节包含完整左右分栏。两块均设置 `min-height:100vh`，支持新视口单位时使用 `min-height:100svh`。全站顶栏和 About 导航保留各自现有作用域，不计入章节的最低高度。两章节在文档流中顺序排列，滚动到第一块下缘后才出现第二块。

使用 `box-sizing:border-box` 将章节内边距计入最低高度。桌面空间足够时内容在章节内垂直居中；短视口、手机、200% 缩放或长文案使内容自然撑大章节。不设置固定 `height`，不隐藏章节的内容溢出，不截断文案，也不把窗口滚动改成嵌套滚动容器或强制滚轮翻页。第一屏标题和舞台可适当收紧留白，以维持原视觉层级。

招募章节设置稳定的 `id="join"`、可编程聚焦的 `tabIndex=-1` 和标题关联。直接打开、刷新 `/aboutus/team#join`，或从其他页面导航到该地址，都应在团队正文和布局准备后定位到招募章节。定位偏移考虑现有粘性站点顶栏；采用当前顶栏实际高度或对应公开高度变量，随字体缩放而调整。

复用 `useReadingPosition` 的就绪等待、hash 定位和无 hash 的历史返回位置恢复。团队页明确 hash 目标优先于普通页首定位，目标存在后完成定位，不因晚到的正文再跳回成员屏；目标获得焦点时使用 `preventScroll`，避免第二次默认滚动。普通成员切换不会修改 hash 或重置滚动。未知或非法编码的 hash 沿用已有兼容行为，不引入全站重定向。

`join` 作为团队页模板的公开语义锚点，在 About 的作者链接校验中登记，允许内容使用 `/aboutus/team#join`；其他未知锚点仍须报错。该地址用于页内导航，不作为开发团队报名的最终外部入口。

验收：高视口两块高度不小于视口，第一屏定位时招募块在视口下方；短视口和手机允许大于一屏且完整可读。分别验证初次打开带 hash、刷新带 hash、站内路由导航、同页 hash 变化、离开后返回，以及无 hash 的既有阅读位置恢复。
## DotGrid 与成员主题

固定的点阵参数如下，布局上容器填满主面板：

```tsx
<DotGrid
  width={1280}
  height={720}
  colorBack={theme.colorBack}
  colorFill={theme.colorFill}
  colorStroke={theme.colorStroke}
  size={2}
  gapX={32}
  gapY={32}
  strokeWidth={0}
  sizeRange={1}
  opacityRange={1}
  shape="circle"
/>
```

默认点颜色为 `colorFill="#ffffff7d"`、`colorStroke="#ffffff"`。初始四位的 `colorBack` 分别为 `#0868de`、`#0c7b6f`、`#7545c4`、`#b44d20`；强调色分别为 `#065ed1`、`#087265`、`#7140bd`、`#ae4617`。这些值是占位配色，不代表实际成员品牌。

人物面板背景、页面主标题强调、头像选中圈和能力图标来自同一个当前成员主题。招募区块独立跟随 Web 的黑白主题，按钮使用深色表面与浅色文字。DotGrid 不以成员 id 重新挂载；颜色变化更新现有 shader 的颜色参数，保持点阵位置稳定。静止状态不启用循环动画，沿用组件默认 `speed=0`。

WebGL2 不可用、初始化失败或上下文丢失时，面板保留该成员的纯色背景和可读内容，选择功能继续可用。Shader 只作用于装饰背景，不接收指针事件。

玻璃选择条使用公共 `ex-glass` 类及已有的 `--exui-glass-*` 可配置值；预览使用 32% 白色底、16px 模糊、细内边和柔和外阴影。正式样式兼容站点浅色／深色主题。基础磨砂效果无需新增 GlassSeed 或折射滤镜；不支持背景模糊时使用 ExUI 的可读背景回退。

## 交互与动画

颜色过渡为 250ms，资料总过渡为 240ms，分别使用 80ms 淡出与 160ms 淡入。曲线采用 `[0.23, 1, 0.32, 1]`。只改变颜色与透明度，不动画化文字位置、容器高度或排版宽度。

点击反馈立即更新选中状态；淡出结束时统一切换姓名、人物和全部资料，避免混合两个人的信息。快速连续切换时中断旧动画，从当前颜色与透明度接续至最新目标，旧回调不得覆盖新选择。重复选择当前成员不重播。

减少动态效果模式移除两阶段退出过程：资料直接更新，仅保留至多 100ms 的颜色与透明度过渡。标签页隐藏或组件卸载时清理进行中的动画；恢复时显示最后选中的成员。

Shader 的颜色参数和普通 DOM 强调色使用同一套 Framer Motion 插值结果；正式实现使用 React 与 Motion 的状态／值订阅，预览中的 MutationObserver 仅用于连接独立 HTML，不作为生产实现。

## 公开配置与兼容边界

`teams` 只负责团队页人物展示，不在本次重建已有 MDX 注册表或迁移项目、Media 的成员引用。保留既有 `community` 字段及其行为。不得把账号、联系方式秘密或草稿资料放入此文件：`public/config.json` 的全部内容本来就会公开。

每项配置定义如下：

| 字段 | 要求 |
| --- | --- |
| `id` | 唯一 ASCII kebab-case 标识。 |
| `name` | 非空姓名或占位名称。 |
| `role` | 非空职责文字。 |
| `bio` | 非空简介文字，按普通文本渲染。 |
| `avatar`、`portrait` | 可选图片，包含 `src`、`alt`、正整数 `width` 和 `height`。 |
| `strengths` | 能力数组，每项包含非空 `title` 与 `description`；图标由展示层的固定 Lucide 选择管理。 |
| `theme` | `colorBack`、`accent` 必填；`colorFill` 默认 `#ffffff7d`，`colorStroke` 默认 `#ffffff`。 |

不增加寄语或计数字段。数组顺序就是头像排列顺序，不增加独立排序字段或编辑后台。`teams` 缺省等价于空数组；空数组展示“成员资料仍在整理中”，隐藏人物舞台，开发团队招募块仍显示。可选图片未提供时不填虚构资源路径。

成员照片仅使用 `apps/web/public/images/team/` 内的公开资源及根相对 URL。校验文件存在性、路径与真实资源边界；照片缺省不需要文件。背景与强调色使用不透明的六位十六进制值，点颜色允许六位或八位十六进制值。校验主面板白色正文、强调色按钮白字的对比度，避免配置破坏可读性。

使用专属的公开配置解析与类型模块，开发启动及构建时验证字段、唯一 id、颜色和图片。浏览器通过 Vite 的 JSON 模块导入取得 `teams`，不调用新增 API，也不运行时 fetch 公开配置。团队配置语义不进入通用 MDX 编译引擎。配置错误报告文件及字段位置，阻止构建；不静默删除非法成员。开发环境修改团队配置后由 JSON 模块 HMR 重新校验和更新展示，失效的当前 id 回到首项或空态。

## 开发团队招募区块

用途：宣传加入 Exre 开发团队，提供明确的团队招募入口。文案围绕共同开发项目、打磨产品与完成作品；不包含收集反馈、提意见、一般社区交流或玩家申请入口。

位置：人物主面板之后。最新视觉参考为 `.notes/previews/team/image copy.png`。采用左右分栏：左侧直接在页面背景上显示品牌标记、大标题、招募说明和三条协作亮点；右侧是独立圆角黑白 MeshGradient 区域，中央承托一张白色玻璃入口卡片。左侧说明加入团队的吸引力，右侧只负责行动入口，不重复介绍创作、开发或团队价值。招募区块的标签、对勾和按钮使用 Web 的黑白主题，与上方成员主题色独立。深色按钮、文字和白色表面直接使用 ExUI 的公开语义颜色，不改变全站主题。桌面两列高度协调，约 580px 的右侧区域为入口提供足够留白；手机按宣传、亮点、加入卡片的顺序单列显示。正式实现使用 ExUI 表面和文字语义色适配浅／深色主题。


右侧背景使用用户指定的 MeshGradient 参数：`colors=["#ffffff", "#000000"]`、`distortion=1`、`swirl=0.2`、`grainMixer=0`、`grainOverlay=0`、`speed=1`、`rotation=90`。底部不显示“开发 / 设计 / 产品体验”方向文字。

背景组件宽高缩小为 `240×264`，通过 CSS 放大铺满视觉区域，并设置 `maxPixelCount=64_000`、`minPixelRatio=1`。以实际 Canvas backing store 验证像素预算，不能只依赖组件宽高：高 DPR 或把组件尺寸覆盖成大容器可能放大实际渲染成本。resize 只调整放大比例；不重建 shader 或提高像素预算。隐藏标签页、背景离屏时暂停，减少动态效果模式使用静态 `speed=0`；卸载清理观察器与 shader。无法使用 WebGL 时保留静态黑白渐变和加入入口。

展示文案：

- 左侧标签：BUILD WITH US。
- 左侧标题：加入 Exre，一起创造。
- 左侧说明：我们正在寻找愿意一起构建的伙伴。用技术打磨体验，让创意成为作品。
- 协作亮点：参与真实项目的开发；与开发者、设计者共同创作；把技术与想法变成作品。
- 右侧标签：NEXT STEP。
- 右侧标题：从这里开始。
- 右侧说明：通过招募入口，了解加入方式。
- 唯一主入口：加入开发团队。

宣传文案由 `team.mdx` 的团队页专用元数据维护，采用 About 的严格字段校验。入口地址由 `apps/web/public/config.json` 中新增的可选 `teamRecruitment.url` 维护。

`url` 允许用户提供的无凭据 HTTPS 地址，或经过现有路由表验证的站内根相对地址。站内目标使用 Router Link，外部目标使用新标签页并设置 `rel="noopener noreferrer"`。不自动借用现有 Rifling 911 玩家申请页、QQ 或 KOOK 玩家社区链接作为开发团队招募地址。

证据缺口：截至本稿修订，仓库没有专属开发团队招募地址，用户尚未提供目标。已经向用户询问实际入口；在地址到达前，预览用禁用的“加入开发团队”按钮和“招募入口待开放”状态展示布局。正式配置缺省或空值时也采用该状态，不输出 `href="#"` 或跳往无关页面。非法的非空地址使配置校验失败。

已确认右侧为简洁的招募入口卡片，点击后连接用户指定的现有渠道。本设计不包含真实申请表单、报名数据处理或候选人审核。

## 可访问性、失败处理与验收

头像使用有可读名称的 button 和 `aria-pressed`；Tab 可访问所有选项，Enter／Space 可选择，焦点不随动画消失。人物和资料是同一个有效选择；旧退出内容如采用双层呈现，必须对辅助技术隐藏。装饰 Shader 标记 `aria-hidden`。页面保持单一 h1、清晰的 h2／h3 层级、入口焦点与现有返回位置恢复。

验证范围：

- 配置：四份占位、缺省与空列表、重复 id、未知字段、非法颜色、路径越界、缺失图片、未知能力字段和长文案。
- 展示：默认成员、全部成员切换、快速反向切换、重复点击、配置更新后的选择恢复、图片失败、无 Shader 时回退。
- 兼容：About 其他页面、MDX 引用／Modal、正文加载与重试、阅读位置、面包屑和文档标题。
- 招募区块：团队招募文案、配置驱动的唯一入口、地址缺省／空值／非法值、站内与外链跳转、链接名称与外链属性。
- 全屏与定位：高／短视口、内容增高、公开 #join 锚点的直接打开／刷新／导航／历史返回、焦点及粘性顶栏偏移。
- 动画：颜色与 DotGrid 同步、中断后只落到最新成员、减少动态效果、后台和卸载清理。
- 真实浏览器：320px、390px、768px、1440px，浅／深色主题、200% 缩放、键盘、长资料和 WebGL 失效。

正式实施后执行 Web 类型检查、相关行为测试、内容检查和 Web 构建；自动检查、真实浏览器验收与部署验收分别报告。当前预览验证不能替代这些实施检查。
