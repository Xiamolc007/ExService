# 支持中心采用登录访问、仓库内容与 ClickUp 官方面板

- 状态：设计已接受；页面与访问边界已实现，反馈提交按六类 v2 方案实现，外部验收单独核对。
- 模块：`support-center`。
- 日期：2026-10-12。
- 设计依据：`.notes/archive/support-center/specs/2026-10-12-support-center-design.md`。
- 技术细化：`.notes/archive/support-center/rfcs/support-center-rfc.md`，当前为 RFC 草案。

## 背景

支持中心为 Website 用户汇集反馈入口、常见错误、具体成员联系方式和开发进度。首期以查找帮助与展示入口为目标，开发工作继续在 ClickUp 中维护。

页面、内容集合与登录访问限制已有实现；反馈提交与外部面板的完整验收不能由页面实现推定。当前认证与通用内容能力分别见 `.ai/architectures/web/authentication-flow.md` 和 `.ai/architectures/web/content-rendering.md`。反馈的当前类型、提交和恢复边界见 `.ai/architectures/support-center/feedback-lifecycle.md`。

## 决策

- 支持首页及其常见错误列表、详情只向登录确认的用户开放。桌面和移动导航同步控制入口；复用 Website 真实会话状态，登录恢复中、匿名或认证不可用时不挂载支持内容及第三方视图。
- 首页「反馈与建议」提供「功能和需求」与「投诉和建议」两张可点击卡片，不显示“即将开放”标签。前者在统一 ExUI Modal 中选择六类反馈并填写普通文本表单，独立 Bug 卡片已移除；后者仍为预留弹窗，不新增管理后台。六类方案见 `.notes/archive/support-center/specs/2026-10-15-support-feedback-redesign-design.md` 与 `.notes/archive/support-center/rfcs/support-feedback-redesign-rfc.md`。
- 反馈卡片保留 3D 图标与说明，标题右侧常驻小箭头，不重复“开始反馈”文案。鼠标悬停使用 160ms 的底色、边框、箭头颜色过渡及约 3px 的箭头右移；键盘聚焦即时显示边框，减少动态效果时取消位移并缩短颜色过渡。
- 常见错误由仓库 MDX 维护，复用通用内容编译与加载能力。首页展示编辑精选案例，可就地展开简短说明、进入同条目的完整详情，也可查看更多；不把精选解释为未经统计的热度排名。
- 联系人展示具体成员的姓名、职责、头像与已确认的联系方式。资料缺失使用真实空态，不发布预览人物或虚构响应承诺。
- ClickUp 使用官方视图嵌入，直接展示在支持首页最后一个业务区块；按 2026-10-13 确认的调整，以 Glass「游戏｜社区｜需求桶」Tab 切换三个分享视图，默认游戏，并移除右侧独立需求桶菜单。首期不新增独立开发页或 API 同步。没有真实嵌入配置时显示空态。
- 视觉沿用本站 About 页的粗体标题、黑白文字和浅灰圆角区块，保留“找到解决办法”的快捷案例设计。样式与主题继续遵循 ExUI 接入约定，不复制设计预览的全局样式或独立 token。

## 原因与后果

仓库内容和官方嵌入复用既有能力，并让团队继续在 ClickUp 更新开发工作。支持页面首期没有新增 HTTP Contract、数据库结构或 Outline 依赖；后来独立的反馈提交按 Contract-first 流程扩展了 HTTP 与反馈记录结构，未改变 Outline 边界。

代价是 Website 无法接管 ClickUp 内部界面和分享权限。本站登录限制负责页面入口与展示；普通公开分享链接和编译后的静态内容不能被视为只有本站登录用户才能读取的秘密资料。跨域 iframe 的 `load` 事件不证明真实任务已经显示，外部面板需要独立浏览器验收。

运营内容必须确认后才能发布；未配置、草稿或预览占位不等于正式可用内容。具体字段、路由接线、来源校验和验收安排留在设计与 RFC 中，不在本条复制。

## 重新审视条件

如果要求 ClickUp 原始数据也受 Website 会话约束、需要自绘开发看板或采用多脚本嵌入，则重新评估相应边界。真实 ClickUp 写入、分享视图及部署仍须分别验收，不得仅因设计、代码或 fake transport 测试通过标记为外部已完成。
